## 修复：添加药品到第 3 步没选时间就自动保存

- 根因（双击派发）：`components/base/primary-button` 内层 view 用 `bindtap="onTap"` 触发
  `triggerEvent('tap')`，而原生 tap 会跨自定义组件边界冒泡到页面上
  `<primary-button bind:tap>`，同一个点击让页面处理函数跑两次。
  `medicine-form` 的 `onNext()` 每次都重读 `this.data.step`（setData 后同步就是新值），
  所以第 2 步点一次「下一步」→ 第 1 次进 next2 把 step 置 3 → 第 2 次直接走 `onSave()`，
  用默认 08:00 落库。第 1 步点一次还会连跳两步（跳过剂量步）。
- 修复 1（根治，全站受益）：`primary-button/index.wxml` 改 `catchtap="onTap"`，原生 tap
  不再外溢，页面只收组件自定义 `tap`。
- 修复 2（纵深）：`medicine-form.onNext` 加 350ms 单步推进锁 + 捕获当前 step；
  `onSave` 前置 `step !== 3 || saved || saving` 直接 return；每次换步 `wx.pageScrollTo(0)`。
- 同类隐患：`返回今日`/`我已服用` 等按钮此前也是双触发（navigateBack 可能连退两页）。
- 验证：`npx tsc --noEmit -p miniprogram/tsconfig.json` 通过。

## 修复：添加药品「返回上一步」不可用

- 根因：`page-nav` 的返回按钮直接 `navigateBack()`，页面里的 `onBack()` 从来没被调用；
  页面上也没有任何「上一步」入口，用户只能退出重填。

  `medicine-form` 传 `intercept-back="{{step > 1}}" bind:back="onBack"`，并在 footer
  左侧加 `primary-button type="sub" label="上一步"`（wxss 加 `.footer__row/__back/__main`）。
- 换步统一 `wx.pageScrollTo({scrollTop:0})`，避免上一屏的滚动位置让时间行落在固定 footer 底下。

## 修复：老人端（爸爸手机）添加服药人「保存失败」

- 现象：老人端加服药人只提示「保存失败」，没有原因。
- 根因 1（权限）：`patient.create/update/archive` 与 `medicine.create/update` 都
  `assertMemberAsync(fid, openid, ct, "admin", "member")`。用「我是吃药的人」身份加入家庭的人
  role 恒为 `elder`（`FamilyJoinHandler`：`roleIntent=="patient" → dbRole="elder"`），
  必然 1003。
- 根因 2（信息丢失，全站）：`utils/request.ts` 的 `ApiError` 只有 `code` + `Error.message`，
  **没有 `msg` 字段**，而全站页面都写 `(e && e.msg) || '保存失败'` → 恒为 undefined，
  1002/1003/1005 全部退化成兜底文案。
- 修复：`ApiError` 补 `msg` 字段（与 message 同值）；老人端提前拦：`pages/medicine.onAdd`、
  `patient.onAdd/onOpen/onSave/onArchive`、`medicine-detail.onEdit/onPlan/onArchive`、
  `medicine-form.onSave` 在 `family.role === 'elder'` 时直接提示「让子女在手机上添加/修改」。
- 判据用 `family.role`（权限）而非 `mode`（渲染），与契约 §4.1 一致。
- 验证：`npx tsc --noEmit` 通过。

## 修复：注销账号后首页无限闪烁 / 白屏

- 现象：`user.erase` 注销后，今日页一直闪「没权限」，重新扫码进白屏且继续闪。
- 死循环链路：
  1. `profile.onErase` 调 `user.erase`，后端删掉 `family_members` 行（软删 user）。
  2. 前端只 toast + `reLaunch('/pages/launch/index')`，**token / store / `booting` 缓存全没清**。
  3. launch 页 `onLoad` 调 `bootstrap()` → 命中 `booting` 缓存直接返回旧结果（不重登），
     于是 `ready=true && family.all.length>0` 成立 → 早退 `reLaunch('/pages/home/index')`。
  4. 首页 onShow → 旧 fid 请求 → 1002 → 老 `handleError` 又 `reLaunch` 首页 → 回到 3，无限闪。
- 修复（前端）：
  - `store/index.resetState()` 清身份相关内存态；`store/user.resetSession()` = clearToken + `booting=null` + resetState；
    经 `utils/auth.setSessionLostHandler` 由 `app.onLaunch` 注册（避免 store↔request 循环依赖）。
  - `profile.onErase` / `family.onLeave` 成功后先 `resetSession()` 再跳 launch。
  - `utils/request.handleError`：1002 不再跳首页，改跳 launch + 3 秒节流（并发失败合并）+ 60 秒内 3 次熔断；
    1003 只 toast 不跳转（原来会把 elder 直接踢回首页）。
  - `pages/home.onShow` bootstrap 失败即 return，不再补发 refreshToday。
- 恢复路径：resetSession → 重登 → families 为空 → launch 欢迎页 → 重新建家。

## 修复：注销后孤儿家庭 + 注销重登收不到推送

- 孤儿家庭：家里只剩一人时注销，家庭变成无成员，药品/记录还在库但任何账号都进不去。
  - 后端 `EraseHandler`：`rest.Count == 0` 时把该家庭 `invite_token`/`invite_expire_at` 置空、
    `member_count=0`（避免无人管理的家仍占唯一邀请码、旧链接还能把人引进来）。
  - 前端 `profile.onErase`：`family.members.length <= 1` 时用强警告文案（"这个家的药品、记录、
    周报将没有任何账号能再打开"），与"家人还在"分开说。
- 注销重登收不到推送：`users.unreachable` 只在 erase 与 PushWorker 失败时置 true，
  **login 从不重置** → 注销后重新注册的账号永远收不到订阅消息，界面上却一切正常。
  修复：`LoginHandler` 登录时 `user.Unreachable = false`。
- 验证：`dotnet build` 0 警告 0 错误；`npx tsc --noEmit` 通过。
- 待办：云端那条已注销账号的 `family_members` 记录要人工补回才能找回旧数据（需运维权限）。
