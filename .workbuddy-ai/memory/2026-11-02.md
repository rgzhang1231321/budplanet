## 全平台药品引用计数 → 「常用药」Top5 + 药名联想（P22）

**口径（主理人两次定稿，别再改回去）**
- 「引用次数」= **所有家庭**填写/使用这个药名的次数，**每次添加 +1、每次删除（归档）−1**，下限 0。
- 计数落库在 `medicine_usage_stats`（V008），按 `name_key` 归一（lower + 去首尾空白含全角空格）跨家庭唯一，
  **不存 family_id / openid / patient_id** —— 这张表本身不含可回指到个人的信息。
- 为什么单独一张表：引用次数是"跨家庭、按药名"的聚合，`medicines` 是"按家庭、按服药人"的行。
  在 `medicines` 上加计数列会让同一个药名在每个家庭各存一份互相矛盾的数，取全平台前 5 还得全表扫。
- 为什么不用内存 GROUP BY（第一版那么做过，被否）：跨家庭聚合拿不到别人的数据。
- 计数 SQL 必须单条原子：`INSERT … ON CONFLICT DO UPDATE SET use_count = use_count + 1`；
  减走 `UPDATE … SET use_count = GREATEST(use_count - 1, 0)`（减到不存在的药名不凭空造行）。
- 写入时机：**create 先计数再建药**（计数失败就当这次没建，避免"报错但药已存在"→ 重试重复占名额）；
  **archive 先归档再计数**（归档已生效，计数失败最多榜单偏高一次）。

**chips 的上榜门槛（重要，别当成 bug）**
- 自定义药名要净次数 ≥ 3（`MedicineUsage.MinCountToRank`）才进 chips；**平台预设名 ≥ 1 即可**。
- 预设豁免的理由：`medicines_common` 本来就是 `/api/medicine/common` 匿名公开的数据，出现不泄露新信息；
  否则上线头几个月 chips 永远是预设原序，看起来像功能没生效。
- 门槛挡的是：低流量期某个人手输的私密药名立刻出现在所有人首页，还能被轮询看出"刚有人加了这个药"。
- 不足 5 条用预设补位；输入联想（q 非空）不受门槛限制，只要 ≥1 就出。

**端点**
- `GET /api/medicine/suggest?fid=&q=`（契约表 v1.5）：`q` 空 = 全平台 Top5 + 预设补位；
  `q` 非空 = 本家庭历史（含已归档，按最近添加）→ 全平台榜 → 预设，去重后最多 8 条。
- 自家药排最前，因为全平台榜会被更热门的药占满，把"我妈在吃的那一个"挤到看不见。
