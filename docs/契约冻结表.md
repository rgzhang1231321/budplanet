## 一、响应封套与错误码

```js
// 成功
{ code: 0, data: { ... }, msg: "ok" }
// 失败
{ code: 1004, data: {}, msg: "超出限额" }
```

| code | 含义 | 前端统一处理 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 未登录 / 登录过期 | 静默重 `user.login` 后重放一次；**打卡链路不得阻塞**（用本地缓存先完成打卡，续期后台做） |
| 1002 | 非家庭成员 | 回首页并刷新家庭列表 |
| 1003 | 权限不足 | 回首页 + toast |
| 1004 | 超出限额 | 弹 `UnlockNudge`（只留「看 15 秒视频」+ 关闭，**无付费出口**） |
| 1005 | 参数错误 | toast `msg` |
| 1009 | 服务异常 | 写重试队列（写操作）／重试 1 次（读操作） |

超时 15s。**所有读接口出参必带 `server_ts`**（东八区判定与 `server_ts+offset` 补偿都靠它）。

`rows[]` 单条字段（**逐字冻结**）：
```js
{ dose_id, pid, slot,                       // v1.2 补 pid/slot：checkin.submit 幂等键是 pid_date_slot，前端缺这两个字段无法构造入参
  medicine_name, dose_text,        // dose_text 为后端已格式化串（"1片"/"半片"），前端禁做中文映射
  due_time,                                  // "08:00"
  due_ts,                                    // ms，UTC
  status,                                    // 仅四值：pending | taken | missed | skipped（types 里不得出现 late）
  is_late,                                   // boolean；「晚服 N 分钟」由前端用 taken_at - due_ts 自己算
  taken_at,                                  // ms；未服为 0/null
  is_corrected,                              // boolean；行尾「已修改」灰字用
  snooze_count,                              // number；上限 2，前端不自累加
  today_index, today_total,                  // 打卡进度「第 2 次 · 共 3 次」，与看板同源
  note }                                     // v1.6 补：用药提示（饭前/饭后/随餐…），打卡卡片显示为标签；无则空串/null
```
- **`slot` 是什么（v1.4 补，★ 实现者必读，别跳过）**：**`slot` = 该时间点在当日的分钟数，取值 0–1439**。`08:00 → 480`、`20:30 → 1230`、`00:00 → 0`。
  - ✅ 是：分钟数整数（`480`）
  - ❌ 不是：「当天第几个时间点」的序号（不是 `0/1/2`）
  - ❌ 不是：`"08:00"` 字符串
  - ❌ 不是：`due_ts`（UTC 毫秒）
  - **三处必须是同一个值**：`rows[].slot`、`checkin.submit.items[].slot`、`dose_id` 的第三段。
  - 存储侧：`plans.slots[].t` 存 `"08:00"` 展示串，派生列 `times_minute INT[]` 存 `480`，**双写、以 `times_minute` 为准**（见 `后端技术方案.md` §四）。
- **`dose_id` 即确定性主键 `${pid}_${date}_${slot}`，直接暴露**。三个写接口的入参口径**各不相同，不要混用**：
  - `checkin.snooze`（`{dose_id}`）、`checkin.correct`（`{dose_id, to_status}`）→ **只传 `dose_id`**，前端不需要拆 pid/date/slot。
  - `checkin.submit`（`{items:[{pid,date,slot,status}]}`）→ **传 pid/date/slot 三字段**，`date` 与 `slot` **直接取 `rows[]` 里的同名值原样回传**；**禁止从 `dose_id` 字符串里解析反推**（拼接串一解析，格式一变就静默错位，且不报错）。
  - `pid` / `slot` 除作入参外，还用于展示与埋点。
  - **v1.4 已删除**：原句「`take / snooze / take_batch` 统一只传 `dose_id`」—— `take` / `take_batch` 自 v1.1 终裁 A 套起即不存在（批量打卡由 `checkin.submit{items:[]}` 承担），且「统一只传 dose_id」与 §7 的 submit 入参直接矛盾。
- **顶层另含 `recentView: {alias, at} | null`**（已读回执：取"昨天、非本人、非 elder"最近一条）。前端**只渲染一行灰字，禁做红点/弹窗/声音** —— 回执的价值是"有人在意我"，变成提醒就变成压力。
- **`dose_text` 是该 slot 展开后的实际剂量串**（"1片"/"半片"）。**用药行与打卡卡片必须渲染 `dose_text`，禁止读药品 `default_dose`** —— 已支持"早 1 片、晚半片"，读默认剂量会让晚上显示成早上的量，**这是安全信息，错了就是吃错量**。
- **历史与周报直接渲染 `dose_text` + `med_name_snapshot` 快照**，不 join 药品表（改名/删 slot 不影响历史）。
- **改计划后必须整树重拉**：改时间点会生成新 `_id`，`pending` 且未到点的旧行由后端删除、已 taken/missed/skipped 的不动。前端**禁止本地乐观复用旧 `dose_id`**，否则点下去拿 422/not_member，表现为"点不动"。

### 7. `checkin`
| action | 入参 | 出参 | 约束 |
|---|---|---|---|
| `submit` | `{items:[{pid,date,slot,status,skip_reason?}], idemKey?}` | `{applied:[{pid,date,slot,status,ts,changed}], rejected:[{pid,date,slot,code,msg}], quota?, server_ts}` | **天生批量，一次 1~N 条**（不另设 take_batch）。幂等键 `pid_date_slot`。**部分成功合法、不整批回滚**。**前端单批上限 8 条**。**`idemKey` 预留，未启用**（v1.7 标注：字段名保留，后端不收读；幂等由「逐条 CAS + 0 行重读再判 `changed`」保证，重复提交得到 `changed:false` 的空操作，不会多记；断网重放按 `applied`/`rejected` 精确出队，不依赖 `idemKey`） |
| `snooze` | `{dose_id}` | `{ok, due_ts, snooze_count}` | `due_ts += 15min`、`snooze_count+1`（上限 2）；**仅允许在 `slot` ~ `slot+snoozeDeadlineMin(45)` 之间调用**，超出返回 1005 |
| `correct` | `{dose_id, to_status:'missed'\|'skipped', reason?}` | `{ok, is_corrected:true}` | **只允许 `taken → missed/skipped` 单向、不可逆**，服务端强校验 + 留审计（操作人/原状态/时间）。仅 admin。**`to_status` 取值域就是 `missed`/`skipped` 两项，不含 `taken`** —— 回 `taken` 是另一件事，走 `submit`（见下方状态迁移第 2 条） |

**`applied[].changed` 语义（必须写死，否则前端队列会错）**：
- `changed: true` = 本次真正写入；`changed: false` = **幂等空操作**（之前已是该状态）。
- 前端出队规则：**`applied` 里无论 `changed` 真假都出队**（结果已确定，重投无害也不会卡队列）；**`rejected` 里仅 `code=1005`（invalid）与 `1003`（not_member）留队并提示用户**，其余按错误码处理。

**允许的状态迁移（v1.2 修订，区分"系统判定"与"人工改判"）**：
- `pending → taken | skipped | missed`
- **`missed（系统判定，`is_corrected=false`）→ taken` 允许** —— 老人确实吃了、只是没打卡，管理员必须能救回误判；不允许则另一个方向的错误（系统误判无人可纠）。
  **通道走 `checkin.submit{status:'taken'}`，不走 `correct`**（`correct` 的 `to_status` 只收 `missed`/`skipped`）—— v1.5 澄清：此前 140 行与本节读起来像互相矛盾，实际是两条不同通道，按此执行
- **`missed（已人工改判，`is_corrected=true`）→ taken` 禁止**，且**禁止对已改判行再次 `correct`** —— 防来回刷数据
- `taken → missed | skipped` 仅经 `checkin.correct`、**不可逆**

> 这条取代 v1.1 的"只允许 `taken → missed/skipped` 单向"字面表述。后者的漏洞是：系统判定的漏服将无人可纠正，而系统误判（吃了没打卡）是这个产品最高频的假阳性。

## 四、模型纪律（v1.1 新增，两条踩过的坑）

### 4.1 `mode` 与 `role` 必须解耦 —— 判老人端一律用 `mode`
| 字段 | 取值 | 职责 | 存储 |
|---|---|---|---|
| `mode` | `elder` / `guardian` | **只决定渲染哪套主题** | per-family 现算（`openid === patients.self_openid` → `elder`），**不落 user** |
| `role` | `elder` / `member` / `admin` | **只决定权限** | 入库 |

**禁止用 `role` 判渲染。** 存在 `role:'admin'` + `mode:'elder'` 的人（子女自己也吃降压药、同时管全家）。用 `role` 判会把他**永久送进子女端主题**（12px 字号），而这类人在本产品中非常常见；更糟的是**它不会报错，只表现为"这个家庭不用了"**，会被误判成留存问题去改产品。

### 4.2 `selfUids: string[]`，不要单值
同一 `openid` 在一个 `family` 内可能绑定多位 `patient`（本人 + 代管）。单值必然绑错或丢数据。`selfUid` 保留 = `selfUids[0]` 做兼容。

## 附录 A · HTTP 路由映射（v1.3 新增，仅为传输载体，不改任何字段）

**v1.3 唯一新增端点**：`GET /api/medicine/common` —— 替代云开发时代 `wx.cloud.database().collection('medicines_common')` 的前端直读（自建后端无前端直读能力）。出参为常用药预设数组，**不含任何新增业务字段**，不改变冻结契约。

**v1.5 新增端点（只读，不改任何已冻结字段）**：`GET /api/medicine/suggest?fid=&q=` —— P22 药名输入联想与「常用药」chips 的唯一数据源。

- **鉴权**：需 JWT，服务端 `assertMember(fid)`。返回里有跨家庭的聚合榜，不能匿名。
- **出参**：`{ items: [{ name, spec, default_dose, count }], server_ts }`。`name/spec/default_dose` 与 `medicine.common` 同名同义；`count` = **全平台**这个药名被添加的净次数（每次添加 +1、每次删除/归档 −1，见 `medicine_usage_stats`，V008），`count = 0` 表示"平台预设补位"，不是被用过的。
- **语义**：`q` 为空 → 全平台引用次数 Top5（次数 ↓ / 最近添加 ↓ / 药名 ↑，不足 5 条用 `medicines_common` 补位）；`q` 非空 → 本家庭历史（含已归档，按最近添加）→ 全平台榜 → 平台预设，去重后最多 8 条。
- **上榜门槛**：**自定义药名**要净次数 ≥ 3 才进 chips，平台预设名 ≥ 1 即可（预设名本来就是 `/api/medicine/common` 匿名公开的数据，出现不泄露新信息）。门槛只为挡住"低流量期某个人手输的私密药名立刻出现在所有人首页"。输入联想不受门槛限制。
- **与 `medicine.common` 并存**：`common` 是匿名可取的平台预设（老版本前端还在调），`suggest` 是全平台榜 + 自家历史。两者**不互相替代**，也**不合并** —— 合并就得给公开端点加 fid 和鉴权，那是改冻结契约。
- **合规边界**：只回药名 / 规格 / 默认剂量三个既有字段 + 一个计数，**不返回适应症、功效、用法建议、相互作用**，不构成 PRD §「明确不做」里的"药品数据库"。
- **隐私边界**：`medicine_usage_stats` 只存药名与计数，**不存任何 `family_id` / `openid` / `patient_id`**；接口不出任何家庭维度，无法反查"谁家在吃这个药"。

**映射纪律**：`types/api.d.ts` 的字段名一律以本表 §一/§二 为准；附录 A 只用于生成请求 URL。前端封装 `call(domain, action, data)` 让业务代码几乎零改动（见 `前端技术方案.md` §6.0）。
