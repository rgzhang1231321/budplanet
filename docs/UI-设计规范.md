# UI 设计规范｜小药盒 · 家庭用药提醒

> 版本 v1.0 ｜ 设计：颜如绘 ｜ 对齐文档：`docs/PRD-小药盒.md` v1.0
> 本文档是前端唯一视觉与交互输入。所有尺寸以 **rpx** 为主单位，括号内标注 **375pt 宽屏（iPhone 6/7/8）下的 px 等效值**，方便对照无障碍标准。
> 遵循《微信小程序设计指南》：导航栏 88rpx、tabBar 98rpx + 安全区、点击热区 ≥ 88rpx（44px）。

## 一、设计原则

| # | 原则 | 具体落地（可验收） |
|---|---|---|
| 1 | **打卡页不是"功能"，是"开关"** | 老人打卡页全屏只有 1 个可点主按钮，从打开到点完 ≤ 2 次点击、≤ 5 秒；页面上无列表、无返回、无广告、无弹窗 |
| 2 | **老人端不让人做选择** | 老人端永不出现：多步表单、二级 tab、下拉筛选、多选；所有分支默认收敛为单一蓝色主按钮 |
| 3 | **子女端给密度，不给噪音** | 首屏（812pt 内）必须同时看到：完成进度、2 位服药人的今日全部用药行、漏服告警；单行信息不超过 3 个字段 |
| 4 | **广告只在"心满意足"和"无聊等待"时出现** | 打卡主流程（提醒 → 打卡 → 成功）前两屏零广告；广告位 A 只在成功动效结束后出现；老人端关闭插屏 |
| 5 | **颜色永远不是唯一信息载体** | 已服/待服/漏服/跳过 四态 = 颜色 + 图标形状 + 文字标签 三重编码，红绿色盲模拟下仍可区分 |

## 二、双端双模方案（核心结论，不含糊）

### 2.1 结论

> **一套页面骨架 + 双层 Design Token + 3 个老人端专属布局变体。**
> 不做两套独立页面，也不做"仅换肤"。

- **复用层（约 80% 代码量）**：页面路由、数据模型、业务组件（用药行、进度环、状态徽标、表单字段）完全共用，只吃 Token。
- **分化层**：`app.globalData.mode = 'guardian' | 'elder'`，由 Token 层注入不同字号阶梯 / 间距 / 圆角 / 色值 / 组件尺寸。
- **3 个必须结构分化的页面**（换肤解决不了）：
  1. `pages/checkin` 打卡页 —— 老人端：全屏单卡；子女端：从看板行点入的半屏卡。
  2. `pages/home` 首页 —— 老人端：无 tabBar、无服药人切换、无药品管理入口，只显示"我的今日"。
  3. `pages/settings` 设置 —— 老人端：6 个开关平铺大字；子女端：分组列表。

### 2.2 为什么不做两套独立页面

单人 4–6 周工期。两套页面 = 双倍 WXML/WXSS、双倍联调、双倍 bug、改一次文案要改两处。而本产品老人端真正需要的结构差异只有 3 个页面，其余页面（周报、邀请、隐私政策）老人几乎不进入 —— 为它们写第二套是纯浪费。

### 2.3 为什么不做"仅换肤"

打卡页的 5 秒目标不是"字更大"能达成的。子女端打卡页承载"补卡、跳过、改时间、看备注"四个操作；老人端必须把它们全部移出首屏。这是**信息架构差异**，不是样式差异。

### 2.4 模式判定与切换

| 时机 | 规则 |
|---|---|
| 首次打开 | 默认 `guardian`（获客入口是子女，见 PRD 第三节） |
| 被邀请落地页 | 邀请卡片携带 `role=patient` 参数 → 加入后自动切 `elder`，并在 P42 落地页用一个大按钮让本人自述「我自己吃药」 |
| 手动切换 | 我的 → 顶部「界面模式」开关，开关本身用大字（见 4.4） |
| 防误触 | 从 `elder` 切回 `guardian` 需二次确认（避免老人误切后彻底不会用） |

**判定数据来源（v1.3，与后端契约对齐）**
- `mode` **由服务端派生、per-family、不落 user**：`mode = exists(patients where family_id==fid and self_openid==openid) ? 'elder' : 'guardian'`。同一个人在自己家是 `guardian`、在父母家是 `elder`。
- **`mode` 与 `role` 必须解耦**：`mode` 只决定**渲染哪套主题**，`role` 只决定**权限**（能否改计划 / 邀请 / 纠正记录）。一个人完全可以是 `role='admin'` + `mode='elder'`（自己吃药、同时管着全家）—— 这正是"子女自己也吃降压药"这一常见人群。**禁止用 `role` 判渲染**，否则这类人的老人端主题永远出不来。
- 后端 `self_openid` 出参为数组 `selfUids[]`（兼容单值 `selfUid`）：脏数据（一人被误绑到两个患者）在数组下能兜住，单值会直接绑错。
- 多服药人家庭：`dose.today` / `board` **在服务端按 `selfUids` 过滤**，elder 收不到其他患者的行 —— 不是下发后前端隐藏。前端过滤能被改一行 where 绕开，服务端过滤不能；健康数据泄露一次就是封号。
- 打卡卡片与用药行的剂量**必须渲染后端下发的 `dose_text`**，不读药品默认剂量 —— 因为已支持「早 1 片、晚半片」，读默认剂量会导致晚上显示成早上的量。

## 三、Design Token

### 3.1 色板

**品牌色**

| Token | 色值 | 用途 |
|---|---|---|
| `--brand-500` | `#2E6BE6` | 主按钮、选中态、链接、进度条 |
| `--brand-600` | `#1E4FBF` | 按压态、深色文字强调 |
| `--brand-100` | `#EAF1FE` | 选中底色、信息卡背景 |
| `--brand-900` | `#0B2B66` | 老人端大字标题（比纯黑更柔和、对比度 13:1） |
| `--warm-500` | `#FF8A3D` | 待办角标、连续达标火焰、"新"标记（家庭感，不与语义色冲突） |

**语义三态（+ 跳过）—— 色盲友好，符合中国习惯**

| 状态 | 填充色 | 文字/图标色 | 图标形状 | 文字标签 | 说明 |
|---|---|---|---|---|---|
| 已服 | `#12A150` | `#0B7F38` | 实心圆 + 白色 ✓ | 「已服」 | 中国习惯：绿=完成 |
| 待服 | `#FFFFFF` + 2rpx 描边 `#A9B4C0` | `#4A5969` | 空心圆环 | 「待服」 | 不用蓝色，避免与品牌色混淆 |
| 漏服 | `#E0402F` | `#C22C1B` | 实心圆 + 白色 ！ | 「漏服」 | 附左侧 4rpx 竖条 + 整行 `#FFF4F2` 底 |
| 跳过 | `#E3E8ED` | `#7A8492` | 实心圆 + 白色 — | 「跳过」 | 中性灰，无负罪感 |
| 同步中 | `#FF8A3D` | `#C25E17` | 顶部细条，无徽标 | 「正在发送给家人…」 | 琥珀=在路上，不是出错；**绝不用红/灰** |
| 存疑（时间异常） | — | `#C25E17` | ⚠ 三角 | 「⚠ 02:41 打卡 · 比计划晚 5 小时」 | 见 §7.4；整行**不做红底**（不是漏服）；不复用 `--st-missed` |

> **色盲验证（Deuteranopia 模拟）**：绿 `#12A150` 与红 `#E0402F` 在红绿色盲下都趋近黄褐，**仅靠颜色无法区分**。因此强制三重编码：① 明度差（绿 L=57%、红 L=49%）；② 图标形状差（✓ / ！/ ○ / —）；③ **始终显示中文状态标签**，任何尺寸下不省略文字。字号 < 24rpx 也不省略，改为图标 + 竖排单字。

|---|---|---|

| `--text-2` | `#5C6B7A` | 次文字 |

### 4.2 每页核心任务

| 页面 | 唯一核心任务 | 成功指标 |
|---|---|---|
| ~~P00~~ → P01 | 选对身份 + 完成免责确认 | 选身份完成率 ≥ 90%（V6 起 P00 已从该入口移除） |
| P01 | 分流到正确模式，避免老人误入子女端 | 分流正确率 ≥ 85% |
| P10 | 3 秒内看到"今天谁没吃药" | 首屏渲染 < 800ms |
| E11/P11 | 点一下「我已服用」 | 完成率 ≥ 75%，耗时 ≤ 5s |
| P22–P24 | 3 分钟内建完一条计划 | 单步流失 < 10% |
| P41/P42 | 让被邀请人无门槛进入家庭 | 邀请点击 → 加入 ≥ 70% |
| P30 | 让子女产生"这数据有用"的感受 | 分享率 ≥ 15% |
| P12/E12 | 让老人主动把"我今天吃药了"发进家庭群 | 分享点击率 ≥ 8%，带来 ≥ 0.2 新增/人 |
| P44 | 让用户看见自己攒下的东西（留存锚点） | 7 日回访率 ≥ 20% |

### 4.3 关键转化漏斗（设计视角）

```
广告/搜一搜 → P01 选身份 → P22 加药 ─┬→ P24 授权(★关键断点) → P41 邀请(★命门) → P42 加入 → E11 打卡
                                              └→ 卡在第 4 个药(E) → 看视频解锁名额 → P44 记录
打卡成功(E12) → 分享"我今天吃药了" → 家庭成员点开 → P42 加入  ← 增长新回路
```
设计资源优先级：**E11 > P24 > P42 > E12 分享 > P10 > P30 > 其他**。
> **v1.3 变更**：产品内所有付费出口已删除（个人主体无支付商户号），原 P44 会员页改为「解锁记录」页。变现只剩广告（Banner / 插屏 / 激励视频）一条路，因此 P44 的目标从"转化付费"改为"留存锚点"。

1. 冷启动进入本页到可点击，≤ 1.2s（本地缓存优先进场，网络后补）。
2. 页面上可点击元素总数 = **4 个**（主按钮、稍后提醒、今天不吃、齿轮）。

6. **当天进度**：与「早上 8:00」同一行右对齐，36rpx `#414D5A`，写「第 2 次 · 共 3 次」。措辞必须用「第几次」不用「还剩几次」（倒计时=压力，方位感=安心）；当天仅 1 次时整行隐藏；本次是最后一次时在按钮下方加 40rpx「今天最后一次了」。`today_index / today_total` 与看板**必须同一 selector / 同一字段**，禁止两页各算各的。
7. **未同步态**：点击即终态（按钮变「✓ 已服用」并锁死防连点），永不出现"提交中"loading 或遮罩；同步状态由顶部 64rpx 琥珀细条表达（见 7.2）。置灰只用于防重复提交，**绝不用于等网络** —— 与前端乐观 UI 的分工在此。
8. **P11 与 P12 合并为一个 page 的两个 state**（`state: 'pending' | 'taken'`），保证按钮收缩→绿环绘制的动效连续、不白屏一帧；但老人端两个 state 都必须满足"可点元素 ≤ 4"，成功态不得新增返回箭头等导航。

**P42 的版式裁决（v1.3，因增长线提高了信息密度）**

增长线要求 P42 加「她已经替你做好了」的叙述 + 具体药单 + 主按钮下灰字「点了就会收到提醒」+ 次按钮描边加粗 + 副标题。这套内容对**家属**有效（降低决策成本、建立信任），但 P42 是**唯一不知道来者是老人还是家属**的页面（知道就不需要分了）。裁决如下：

1. **整页按"向弱侧倾斜"渲染**：字号 ≥36rpx、主按钮 160rpx、次按钮 120rpx —— 即老人规格。理由是：如果来者是老人，他是最需要大字的一方；家属看到大字只是"大"，不损失任何理解。**不要为 P42 做两套版式**（做不了，页面加载时身份未知），也不要按家属规格渲染（会让老人直接卡在这一页）。
2. **信息密度按家属版，但用大字承载，且限量**：药单**最多列 2 条 + 「等 N 种药」**（与 §7.4 批量折叠规则一致）；副标题限 1 行；主按钮下方的说明灰字限 1 行。
3. **两处必须改掉的规格**（增长线的原始参数会破适老化红线）：
   - 「点了就会收到提醒」原定 32rpx —— **老人端最小字号 36rpx 是硬约束**（32rpx≈16px）。改 36rpx。
   - 原定色 `#8A94A0` 在白底上对比度约 3.1:1，**老人端要求 ≥7:1**。改 `#414D5A`（8.2:1）。次按钮描边加粗到 2rpx `--brand-500` 可以保留。
4. **一屏装完，不许滚动**：老人不会想到往下滑，会以为页面就这些然后退出。若内容超屏，砍药单条数（2→1→0），不要砍按钮。

### 6.3 让广告不伤体验的 5 个手法

1. **A 位绑定"正向时刻"**：打卡成功的多巴胺还没消退时展示，用户此刻最宽容（PRD 6.2 原话）。
2. **B 位永不吸底**：吸底 Banner 是老人最容易误触的东西，误触 = 卸载。放在列表末尾，用户滚动到才有曝光 —— 少赚一点，留住 7 日留存。
3. **C 位三条件互锁**：冷却 + 日上限 + 时段屏蔽。任何一条不满足就不弹。
4. **D/E 位给"明确交换"**：不是"看广告"，是"看 15 秒视频换详细报告"。文案顺序固定为**成本在前、权益在后**（「看 15 秒视频，查看详细报告」），用户预期明确、无被骗感。
5. **广告容器统一白底描边 + "广告"角标**：合规（《广告法》标识要求）且降低"被骗"感。

**文案规则**（合规红线 8.6：不得诱导、不得批量静默请求）
- ✅ 可说：「开启提醒，到点手机会响」「可随时在设置里关闭」

- 授权按钮点击后立即调用 `wx.requestSubscribeMessage`，**一次只申请 1 个模板 ID**（避免批量请求触发审核问题），模板为"用药提醒"。
- 用户选择「总是保持以上选择」→ 后续调用静默通过，产品体验才成立。引导文案必须明确说出这一点，这是本产品最关键的转化文案。
- 若用户拒绝（`errCode = 20004`）→ 不重复弹窗，改为页面内提示条：「提醒未开启，你也可以在打开小程序时看到今日用药」，并在 P40 我的页常驻一条红点未完成项。
- 老人端不主动发起授权（老人不会操作），由子女在 P41 邀请后的「提醒设置」中代持说明：「提醒会发到你自己手机上，请让家人帮你点一次开启」。

### 7.2 打卡成功反馈动效（分层 1.2s）

| 时间 | 老人端 / 子女端表现 |

| 0ms | 主按钮 scale 0.96 + `wx.vibrateShort({type:'heavy'})` |

**老人端**：不显示任何红色漏服警告。漏服对老人只有"待服"一种表达，避免焦虑与抵触（核心：老人愿意每天点按钮 > 一切）。

### 7.4 打卡记录的可信度（v1.1 新增 · 两条安全网）

> 背景：老人端取消撤销后，存在"没吃的药被点成已服、子女看到已服就不再追问"的静默漏服风险。而本产品的全部价值就是让漏服被发现。以下两条是这条设计的必要配套，**不可只做其一**。

**安全网一：已服记录必须带打卡时间戳**

| 项 | 规格 |
|---|---|
| 显示位置 | 用药行内、状态徽标下方，24rpx `—text-3`（`#8A94A0`），文案「08:12 打卡」 |
| 与计划时间并置 | 左侧槽位保留计划时间「08:00」，右侧显示实际打卡时间，两点并置才能读出偏差 |
| 异常判定 | ① 与计划时间偏差 > **120 分钟**；② 打卡时间落在 **00:00–05:00**。命中任一即判异常 |
| 异常样式 | 文字转 `#C25E17` + **前置 ⚠ 图标**（图标形状编码，不能只靠颜色，遵守 §3.1 三重编码原则）；整行不做红底（这不是漏服，是"存疑"） |
| 异常文案 | 「⚠ 02:41 打卡 · 比计划晚 5 小时」；凌晨打卡固定加一句「这个时间不太对，确认一下？」 |
| 端差异 | **仅子女端显示**。老人端 E10 不显示时间戳（会突破 ≤4 元素的密度上限，且老人无法据此做任何决策） |
| 行高影响 | 不变，仍 112rpx（时间戳占徽标下方的 24rpx 副行槽位） |

**安全网二：改状态必须是显式两步操作，且留痕**

- **入口**：用药行右侧「⋯」可点按钮（热区 88rpx）。**不用右滑、不用长按** —— 长按与行点击冲突，且违反 §10 第 6 条"不依赖手势"，50 岁的子女也不会去试。
- **步骤**：点「⋯」→ 原生 `wx.showActionSheet`（改为已服 / 改为漏服 / 改为跳过 / 取消）→ **三项改动全部要走 `wx.showModal` 二次确认**（v1.3 明确：原只写"漏服/跳过"要确认，但"把漏服改成已服"同样污染用药史、而且更严重——它会把漏服洗成完成）。确认文案「把 08:00 降压药改成漏服？这会记入用药史」。两步都是原生组件，实现成本低且天然不可误触。
- **留痕**：被管理员手动改过的记录，行尾加 20rpx 灰字「已修改」，并在周报里**单列**"手动修改 N 次"。理由：用药史是这产品唯一沉淀下来的资产，手动修改若混进完成率，等于让用户自己污染自己的数据。
- **完成率口径（硬规则，主理人 v1.2 升级）**：**完成率只统计「系统判定 + 老人自主打卡」，人工修改的记录单独计数、不参与完成率计算。** 否则子女改两次就能把完成率刷到 100%，北极星指标立刻失去意义。周报页与看板概览卡必须按此口径计算，且分母 = 计划次数、分子 = 自主完成次数，两者都不含人工修改。
- **不可逆性（v1.3 精确化）**：不可逆针对的是**"人工做出的漏服判定"**，不是"系统判定的漏服"。即：系统判定为 `missed` 的记录，管理员可补记为 `taken`（老人确实吃了只是没打卡，这是最常见场景，必须放开）；但一旦管理员已把它人工改成 `missed`/`skipped`（`is_corrected=true`），就不能再改回 `taken`。一句话：**系统判的漏服可以救，人判的漏服不能翻。** 服务端强校验，前端置灰只是体验层。

## 十一、给前端（程前锦）的对接说明

1. **Token 落地方式**（v1.1 勘误：原写 `page[data-mode]` 属性选择器**在微信内不生效**，`page` 是框架层节点无法绑 `data-*`）：默认值写 `page{}`，`elder` 覆写挂页面根节点 `.p-root.elder{--fs-body:40rpx;…}`，切模式只 `setData` 一个字段。page 自身背景色用 `wx.setBackgroundColor` + `wx.setNavigationBarColor` 补（正好实现老人端纯白全屏）。字号统一走 `--fs-body` 类变量，**禁止页面内写死 rpx 字号**。
   - **覆盖风险（设计验收项）**：任何 fixed 弹层（订阅引导、解锁引导 `UnlockNudge`、AdSlot、ActionSheet 自绘部分、分享提示气泡）**必须挂在 `.p-root` 内部**，否则会掉回子女端字号 —— 这是本方案最容易静默失败的地方。加两条 CI 检查：`grep -rn "font-size: *[0-9]\+rpx" pages/` 必须为空；`grep -rL 'p-root' pages/**/*.wxml` 必须为空。
2. **打卡页性能**（v1.1 勘误：**改为留主包，不独立分包**）：订阅消息点开是冷启动，分包首次进入要下载代码（弱网 1–3s），会直接击穿 1.2s 硬指标，且用户从未访问主包、预下载来不及。主包预算 ≈ 250KB（4 tab 薄壳 130 + checkin 40 + 启动/声明 20 + 共享组件 45）远低于 800KB 上限，重业务已下沉。付代价换来的要求：`checkin` 不得 import 任何重依赖（图表/时间库/富文本），首屏只依赖本地缓存 `next_dose` + 一个轻接口；**打卡流程不得被登录态阻塞**（登录过期时仍可用本地缓存完成打卡，后台静默续期）。
3. **广告不阻塞**：`AdSlot` 组件自带宽高比占位（A: 210rpx，B: 200rpx，B': 180rpx），先渲染占位骨架再挂载 ad，避免 layout shift。广告失败必须静默折叠为 0 高，不留空白。
4. **老人端禁用动效性能开销**：成功动效纯 CSS/SVG，不用 canvas，不引入 Lottie。
5. **tabBar**（v1.1 勘误：`wx.hideTabBar()` 会先闪一下，老人会去点）：改用 `tabBar.custom: true` 自绘，`elder` 模式**根本不渲染**，零闪烁。自绘 tabBar 需含 98rpx + 安全区；老人端不渲染 tabBar 后，页面底部必须保留 `env(safe-area-inset-bottom)` padding，否则主按钮会贴住 home indicator。
6. **状态色变量名**：`--st-taken / --st-pending / --st-missed / --st-skipped / --st-syncing / --st-warn`，与后端枚举一一对应，不做二次映射。
7. **【交增长线 growth-ops】单人家庭组的观测要求（v1.2 新增）**：设计侧已裁决"纯老人无 guardian 的家庭组不做补救提示"（不在非目标场景给老人加他无法处理的文案），但**必须观测**，由增长线看板承担：
   - 家庭组按「有 guardian / 无 guardian」两个维度单列：**占比、7 日留存、打卡完成率**三项。
   - 判定阈值：若单人家庭组**占比 > 25% 且 7 日留存明显低于多人家族群**（建议以相对差 ≥ 20% 为界），说明"家庭协同"假设部分失效 → 再决定是补提示还是改引导，不要现在就加 UI。
   - **完成率埋点口径**：分子 = 老人自主打卡次数，分母 = 计划次数；**人工修改的记录只单独计数（`manual_edit_count`），不进分子也不进分母**（同 §7.4 硬规则）。这条口径若不统一，增长侧所有留存对比都会失真。
   - 设计侧的原则立场：**事前引导优于事后提示** —— 与其第二天告诉老人"记录存疑"，不如第一天就让子女把家人拉进来。因此邀请页的「邀请家人一起看」保持为默认下一步的强引导（见 §5.5），这是本条观测的配套动作，不要为了观测指标而削弱它。
   - 埋点最小集：`family_id / member_count / has_guardian / role / invite_source / checked_by(self|manual) / checkin_time_vs_plan_minutes`（最后一项用于验证 §7.4 异常阈值的合理性）。

---

**设计取舍一句话总结**：以「打卡页是开关不是页面」为最高优先级，用一套 Token 双主题复用 80% 代码、只对打卡/首页/设置三页做结构分化，并在老人端主动放弃插屏与激励视频收入，换 7 日留存与家庭裂变。
