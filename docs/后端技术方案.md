## 〇、迁移摘要（这次到底改了什么）

| 维度 | 旧方案（云开发） | 新方案（自建） | 影响 |
|---|---|---|---|

| 微信接口 | 云函数内直调 | 自建 access_token 中控（单实例内存锁 / 多实例分布式锁） | 见 §七 |

| 开发期数据库 | 云环境 | 本机 Docker `medbox`，**0 元** | 已建库并跑通首批脚本 |

**保留不动的三样东西**（这是原方案最值钱的部分，别在迁移里丢掉）：
1. **时间轮物化调度**：`dose_logs` 确定性主键 + `due_ts` 索引当槽位 + 三道幂等。
2. **契约冻结表**：11 个业务域、字段名、`code 1001–1009`、`server_ts`、四态枚举 —— 逐字不动，只把"云函数 action"映射成 HTTP 路由。
3. **订阅消息额度池与四级降级**：业务逻辑原样，只换发送执行器。

## 三、信任根迁移 ★ 本次最大风险项

### 3.1 旧方案为什么"安全得省事"
云开发的 `cloud.getWXContext().OPENID` 由微信服务端注入，客户端**无法伪造**，所以前端"永不传 openid"这条铁律天然成立。

### 3.2 新方案必须自己造这个信任根

```
小程序 wx.login() → code
   │ POST /api/user/login  { code }
   ▼
服务端 WxApiClient.Code2Session(code)   [appid + secret + code → openid + session_key + unionid]
   │  ★ session_key 绝不下发前端（可用于解密，泄露=会话劫持）
   ▼
签发 JWT（HS256，30 天）+ RefreshToken
   Claims: { sub=openid, unionid?, jti, iat, exp }
   │  返回 { token, refreshToken, openid, user, families[], entitlement, config, server_ts }
   ▼
前端 storage 存 token；后续请求头 Authorization: Bearer <token>
   ▼
JwtBearer 中间件校验签名/过期 → HttpContext.User.FindFirst("sub") = openid
   ▼
IMemberGuard.AssertMember(familyId, openid, needRole) —— 所有涉及 fid 的入参，服务端二次校验
```

### 3.3 六条硬规则（写进代码评审单点检查）

1. **前端永不传 openid**（沿用冻结表铁律）。任何接口入参出现 `openid` 字段 → 直接忽略或报 `1005`，绝不采信。身份只从 JWT Claims 取。
2. `session_key` 只存服务端（可加密落库/缓存），**永不下发**。
3. JWT 密钥来自环境变量 `JWT__SECRET`（≥32 字节随机），**禁止硬编码、禁止进 git**。本地用 `dotnet user-secrets`。
4. `code2session` 必须校验返回 `errcode`；`appid/secret` 走配置，不落前端。
5. `assertMember` 在**每个**涉及 `fid` 的用例第一行调用，越权统一返回 `1002/1003` 并写 `audit_logs`（不泄露"家庭是否存在"）。
6. 打卡链路不因 token 过期阻塞：前端本地队列先完成打卡，后台静默 refresh 后重放（沿用契约 1001 处理）。

### 3.4 多实例下的会话一致性
JWT 无状态，天然可水平扩展；`RefreshToken` 落 `users`/独立表并支持撤销。access_token 中控见 §七，多实例时用 PG advisory lock（`pg_try_advisory_lock`）保证只有一个实例刷新，避免互相踢掉。

## 四、数据模型映射（Mongo 集合 → PG 关系表）

完整 DDL 见 `db/migrations/V001__baseline_schema.sql`（已在 `medbox` 跑通）。此处只记**迁移时的三个关键裁决**：

1. **`dose_id` 口径统一到契约冻结表**：`= ${patient_id}_${due_date}_${slot}`，`slot = due_minute(0–1439)`。
   - 旧云开发方案 §3.7 写成 `${plan_id}_${date}_${minute}`，**是被修正的旧稿**。以契约冻结表为准。
   - 好处：`checkin.submit` 的幂等键 `pid_date_slot` 与 `dose_id` 完全等价，前端零拼接，重投即命中。
2. **数组字段的两种处理**：
   - `plans.slots`（对象数组）→ `JSONB` + 派生 `times_minute INT[]`（GIN 索引），保留"1 药品:1 计划:多 slot"语义，避免拆表带来的 join 复杂度。
   - `users.family_ids` / `families.member_openids` 等冗余数组 → 以 `family_members` 关联表为准，冗余列仅作登录加速，可由关联表派生/校验。
3. **时间戳统一 `BIGINT` UTC 毫秒**（`due_ts`/`taken_at`/`created_at`），自然日 `due_date` 存东八区字符串。忠实还原冻结契约，规避时区换算 bug；范围查询走 B 树，性能等价。`status` 用 `VARCHAR + CHECK` 冻结四值，不用 PG enum（加值也要写脚本，CHECK 更直观）。

**EF Core 映射约定**（`Infrastructure/Persistence/Configurations/*.cs`）：
- `ToTable("dose_logs")` 显式指定小写表名；属性用 `[Column]` / `HasColumnName` 对齐 snake_case。
- `BIGINT` ↔ C# `long`；`JSONB` ↔ `string`（`HasColumnType("jsonb")`，序列化在应用层）；`INT[]`/`TEXT[]` ↔ `int[]`/`string[]`（Npgsql 原生数组）。
- `HasKey(d => d.DoseId)` 用确定性字符串主键；**禁用** `ValueGeneratedOnAdd()` 的自增 ID 作为业务主键。
- `DbContext` 构造注入 `TimeProvider`，所有 `created_at` 由应用时钟生成（TDD 可注入 FakeTimeProvider）。

## 五、数据库变更规范（SQL 脚本先行 · 铁律）

**详细规范与执行器见 `db/migrations/README.md` 与 `db/apply.sh`。** 要点：

- **禁用 EF Migrations**：不装 `EFCore.Design`，禁止 `Database.Migrate()` / `EnsureCreated()`。CI 加静态扫描，出现即失败。
- **文件命名** `V{NNN}__{snake_case}.sql`，序号从 `001` 起**严格 +1**，断号/重号/乱序执行器直接拒绝。
- **append-only**：已执行脚本内容用 SHA-256 记入 `schema_migrations` 账本；被改动 → dry-run 报错并要求"新增版本"修复，禁止改旧脚本。
- **下一个可用版本固定为 `V004`**（当前 `V001–V003` 已执行）。任何人不得跳到 `V010`。
- **幂等 + 单事务**：脚本用 `IF NOT EXISTS` / `ON CONFLICT DO NOTHING`，包在 `BEGIN/COMMIT`，失败整体回滚。
- **三层数据库隔离**：本地开发 `medbox`；集成测试 Testcontainers 一次性容器；生产独立实例。测试库与 `medbox`/`ragdb` 完全隔离。

**已执行基线**（`medbox`，2026-10-29 验证）：`V001 建表(19 张业务表 + 账本)` → `V002 索引(48 条)` → `V003 种子(app_config + 6 常用药)`。

## 六、提醒调度迁移（时间轮算法保留，只换执行器）

### 6.1 保留的核心思想（原方案 §四，逐字不动）

> 把"提醒时间"物化成带确定性主键的 `dose_logs` 行，让 `due_ts` 索引充当时间轮槽位；每分钟的 tick 只做一次 1 分钟宽度的索引范围查询并入队，真正的推送由分片 worker 从队列消费 —— 扫描与发送彻底解耦，靠"确定性主键 + 条件更新 CAS"实现三道幂等。

### 6.2 执行器从云函数 cron → `BackgroundService`

| 旧（云函数） | 新（BackgroundService） | 触发 |
|---|---|---|
| `materializer` cron 00:10 | `MaterializerWorker` | 每天 00:10（东八区），`PeriodicTimer` + `TimeProvider` |
| `reminder-tick` cron 每 1 分钟 | `ReminderTickWorker` | 每 60s，扫 `[now, now+60s)` + 漏服兜底 15min 滑窗 |
| `push-worker` 事件 | `PushWorker`（分片 Channel 消费） | tick 入队后内存 Channel 触发 |
| `weekreport` 周日 20:00 | `WeekReportWorker` | 每周日 20:00 |
| `archive` 03:30 | `ArchiveWorker` | 每天 03:30 |
| `stats` 00:30 | `StatsWorker` | 每天 00:30 |
| `warmup` 每 5 分钟 | **删除** | 常驻进程无冷启动，无需预热 |

**为什么用 `PeriodicTimer` 而不是 Quartz/Hangfire**：项目只需要 5 个固定周期任务，`PeriodicTimer` + `TimeProvider` 是 .NET 原生、零额外依赖、且**可被 FakeTimeProvider 完全控制**（TDD 关键，见 §九）。引入调度框架反而增加锁版本与运维成本。

### 6.3 三道幂等锁在 PG 里的等价实现

| # | 旧（Mongo） | 新（PostgreSQL） |
|---|---|---|
| ① 生成 | `_id` 确定性，duplicate key 静默跳过 | `INSERT ... ON CONFLICT (dose_id) DO NOTHING` |
| ② 入队 | `push_tasks._id` = md5(...) | `INSERT ... ON CONFLICT (task_id) DO NOTHING` |
| ③ 发送 | `update({status:'queued'})` 校验 `stats.updated===1` | `UPDATE push_tasks SET status='sending' WHERE task_id=@id AND status='queued'`，校验 `ExecuteUpdateAsync()` 返回受影响行数 `==1`；并发用 `FOR UPDATE SKIP LOCKED` |

> PG 的 `UPDATE ... WHERE ... AND status='queued'` 返回受影响行数，就是可靠的 CAS 返回值；`FOR UPDATE SKIP LOCKED` 让多实例/多线程安全分片，**不引入 Redis 也能做分布式队列**。这比 Mongo 更强。

### 6.4 两个易漏场景（原样保留）
- **改时间点**：删除该 plan + 今天 + `due_ts>now` + `status='pending'` 的旧行，重新生成；**已打卡行绝不删**。
- **稍后提醒**：直接 `due_ts += 900000`、`remind_status=0`、`snooze_count+1`（上限 2），扫描条件仍只有 `due_ts` 一个。

### 6.5 时间轮逻辑必须可 TDD
`ReminderTickWorker` 的"扫哪些行、入哪些队、额度不足时只保当日最早 slot"这部分**抽成纯函数/领域服务**（输入：一批 dose_log + 额度 + 当前时间；输出：待入队 push_tasks + remind_status 变更），用 `FakeTimeProvider` 注入，单元测试覆盖 `07:00–09:00` 峰值、跨天、snooze、漏服兜底窗口。

## 七、微信接口中控（access_token 与订阅消息）

- **access_token 中控**：`AccessTokenProvider` 单例，缓存 token + `expires_at`，提前 5 分钟刷新。单实例用 `SemaphoreSlim` 防击穿；**多实例用 PG `pg_try_advisory_lock(key)`**，抢到锁的实例刷新并写缓存表，其余等待读缓存。这是云开发内建能力迁到自建后必须自己补的一环。
- **订阅消息发送**：`subscribeMessage.send` 走中控 token；失败按 errcode 判决表处理（`43101` 拒收不重试、`47003` 参数错立即告警、`-1/45009` 指数退避最多 3 次、`40003` 标 unreachable）。判决表原文见 `后端云开发方案.md` §4.5，逻辑不变。
- **内容安全**：服务端调 `msgSecCheck` 校验 UGC 文本（药名备注、家庭名），`87014` 命中即拒；埋点上报**不得含药品名/疾病名/剂量文本**（沿用冻结表）。

## 八、HTTP API 契约映射（11 域 · 逐字对齐冻结表）

> **契约冻结表 v1.2 仍是唯一真相源。** 本次迁移**不改任何字段名/结构/错误码**，只把"云函数 action 路由"改成 HTTP 路由。前端 `types/api.d.ts` 字段照旧。

### 8.1 路由映射规则

统一前缀 `/api/{domain}/{action}`，`POST` 为主（写操作幂等重投友好），读操作用 `GET`。请求/响应封套不变：

```js
// 成功
{ code: 0, data: { ... }, msg: "ok", server_ts: 1761753600000 }
// 失败
{ code: 1004, data: {}, msg: "超出限额" }
```

**所有读接口 out 必带 `server_ts`**（UTC 毫秒，东八区判定与时钟补偿都靠它）。全局中间件统一注入，业务用例不重复写。

| 域 | 云函数 action | HTTP 路由 | 方法 |
|---|---|---|---|
| `user` | `login` / `agree_privacy` / `agree_disclaimer` / `export` / `erase` | `/api/user/login` … | POST |
| `family` | `create` / `join` / `info` / `list` / `update_role` / `leave` / `reset_invite` | `/api/family/{action}` | POST / GET(list,info) |
| `patient` | `create` / `update` / `archive` / `list` | `/api/patient/{action}` | POST / GET(list) |
| `medicine` | `create` / `update` / `archive` / `list` | `/api/medicine/{action}` | POST / GET(list) |
| `medicine` | **`common`**（v1.3 新增只读端点） | `/api/medicine/common` | GET（公开，替代原云开发前端直读 `medicines_common`） |
| `medicine` | **`suggest`**（v1.5 新增只读端点） | `/api/medicine/suggest?fid=&q=` | GET（需 JWT + `assertMember`；`q` 为空取全平台引用次数 Top5，非空取联想） |
| `plan` | `create` / `update` / `finish` | `/api/plan/{action}` | POST |
| `schedule` | `today` / `week` | `/api/schedule/today?fid=&date=` | GET |
| `checkin` | `submit` / `snooze` / `correct` | `/api/checkin/{action}` | POST |
| `notify` | `ack` / `quota` | `/api/notify/{action}` | POST / GET(quota) |
| `ad` | `unlock` | `/api/ad/unlock` | POST |
| `report` | `batch` | `/api/report/batch` | POST |
| `config` | `get` | `/api/config/get` | GET |

> 保留"单域多 action"的好处：11 个 Controller 对应 11 域，与冻结表 11 函数一一对应，前端调用层改动最小（从 `wx.cloud.callFunction({name,data})` 换成 `request.post('/api/{name}/{action}', data)`，见前端方案 §六）。

### 8.2 错误码（逐字不动，全局异常中间件统一转换）

| code | 含义 | 前端处理（沿用冻结表 §一） |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 未登录/过期 | 静默 refresh 后重放一次，**打卡链路不阻塞** |
| 1002 | 非家庭成员 | 回首页刷家庭列表 |
| 1003 | 权限不足 | 回首页 + toast |
| 1004 | 超出限额 | 弹 `UnlockNudge`（只留看视频 + 关闭，无付费出口） |
| 1005 | 参数错误 | toast msg |
| 1009 | 服务异常 | 写操作进重试队列 / 读操作重试 1 次 |

**领域异常 → code 的映射**放在 `Middleware/ExceptionHandlingMiddleware`一处：`NotMemberException→1002`、`ForbiddenException→1003`、`QuotaExceededException→1004`、`ValidationException→1005`、其余 →1009 + 记日志。超时 15s（Kestrel + `RequestTimeout` 中间件）。

### 8.3 三个必须原样保留的契约细节（迁移最易翻车处）

1. **`schedule.today` 的 `rows[]`**：字段逐字冻结，`dose_id` 即确定性主键直接暴露；`checkin.snooze` / `checkin.correct` 只传 `dose_id`（`checkin.submit` 反传 pid/date/slot 三字段，见冻结表 §6）；顶层 `recentView` 只渲染一行灰字、禁红点弹窗声音。**改计划后必须整树重拉**，前端禁本地复用旧 `dose_id`。
2. **`dose_text` 格式化规则**：后端统一出（`slots[i].d || medicine.default_dose || ""`），**后端不解析数值、不做 `0.5→"半片"` 转换**；`dose_logs` 冗余快照，历史不 join 现算。前端禁做中文映射。
3. **`checkin.submit` 批量语义**：`{items:[...]}` 天生批量，单批上限 8；`applied[].changed` 语义写死（true=真写入 / false=幂等空操作，两种都出队）；`rejected[]` 仅 1005/1003 留队；**部分成功合法、不整批回滚**。状态迁移：`pending→taken|skipped|missed`；`missed(is_corrected=false)→taken` 允许；`missed(is_corrected=true)→taken` 禁止；`taken→missed|skipped` 仅经 `correct` 且不可逆。

## 九、权限模型（信任根换了，规则不变）

三级角色矩阵（`admin/member/elder`）与原方案 §7.1 完全一致。变化只在"openid 从哪来"：

- 旧：`cloud.getWXContext().OPENID`（服务端注入）。
- 新：JWT Claims 的 `sub`。**`IMemberGuard` 接口封装**，所有用例第一行调用，前端传什么都不信。

```csharp
// Application/Common/AssertMember.cs —— 唯一真相源，伪代码示意
public async Task<MemberContext> AssertMember(string fid, string openid, Role need = Role.Elder)
{
    var m = await _db.FamilyMembers
        .AsNoTracking()
        .FirstOrDefaultAsync(x => x.FamilyId == fid && x.Openid == openid);
    if (m is null) throw new NotMemberException();            // 统一 1002，不泄露家庭是否存在
    if (m.Role < need) throw new ForbiddenException();        // 1003
    if (m.Role == Role.Elder && m.SelfPatientId is not null)
        return m with { ScopePatientId = m.SelfPatientId };   // elder 只能操作自己绑定的服药人
    return m;
}
```

- **`checkin.correct` 更严**：仅 `admin/member`，`elder` 一律 1003（老人端 UI 不给入口，但服务端不依赖"前端不会调"）；必须独立写 `correct_logs` 审计。
- **越权即审计**：所有 `1002/1003` 写 `audit_logs`（openid/fid/action/时间），用于发现扫描行为。
- **PG 层兜底**：应用账号最小权限（不使用 superuser 直连生产），关键表可加 RLS 作为纵深防御（P1，非必须）。

## 十、TDD 开发模式（主理人指定，写进流程）

### 10.1 铁律：红 → 绿 → 重构

**任何业务代码先写测试，测试先失败，再写实现让它变绿，最后重构。** 禁止"先写实现后补测试"。CI 强制覆盖率门禁：Domain ≥ 85%、Application ≥ 75%。

### 10.2 三层测试策略

| 层 | 工具 | 连库？ | 测什么 | 速度 |
|---|---|---|---|---|
| **Domain 单测** | xUnit + FluentAssertions | 否 | 状态机、额度预算、完成率、幂等键、东八区日期 | 毫秒级（红绿主战场） |
| **Application 用例测试** | xUnit + NSubstitute | 否（mock `IAppDbContext`/`IWxApiClient`/`IClock`） | 登录、建家庭、打卡、改判、限额、越权 | 毫秒级 |
| **Integration 集成测试** | Testcontainers.PostgreSql + WebApplicationFactory | 是（一次性 `postgres:18-alpine` 容器） | 真实 SQL 约束、CAS、事务、API 端到端、脚本可重建 | 秒级 |

集成测试启动流程：`Testcontainers` 起容器 → `db/apply.sh` 顺序跑全部 V*.sql → 断言 schema/CHECK/索引 → 跑用例 → 容器销毁。**与 `medbox`/`ragdb` 完全隔离**。

### 10.3 必测用例清单（按域，验收时逐条对）

**Domain（纯函数，最先写）**
- [ ] `DoseStateMachine`：`pending→taken/skipped/missed` 合法；`missed(未改判)→taken` 合法；`missed(已改判)→taken` 抛错；`taken→*` 仅经 correct；四值之外状态拒绝。
- [ ] `CompletionRate`：`manualCorrectCount` 单列、不进分子分母（防刷北极星）；`skipped` 不计漏服。
- [ ] `QuotaBudget`：额度不足时"只保当日最早一次 slot"，其余置 `remind_status=3`（§6.2.1）。
- [ ] `IdempotencyKey`：`dose_id = ${pid}_${date}_${slot}` 与 submit 幂等键恒等；重投命中。
- [ ] `BjDate/EpochMs`：UTC→东八区 `YYYY-MM-DD` 跨天正确；"早上 8 点不跑到前一天"。
- [ ] `WeekKey`：`2025-W03` 生成与周报聚合边界。

**Application（用例）**
- [ ] `UserLogin`：code2session 成功→签 JWT + 返回 config/families；errcode 非 0→1009；session_key 不下发。
- [ ] `FamilyJoin`：`role` 出参恒为 admin/member/elder；入参 `role:'patient'` 落 elder 且**只在此时**写 patients.self_openid；`mode` 按 self_openid 现算返回 `selfUids[]/selfUid`。
- [ ] `CheckinSubmit`：批量 1~N；>8 返 1005；`changed` 语义；部分成功不回滚；幂等三部曲（idemKey 10min → 逐条 CAS → changed 判定）。
- [ ] `CheckinCorrect`：起点仅 taken；不可逆；已改判拒绝再次 correct；必写审计；elder 1003。
- [ ] `MedicineCreate`：免费第 4 个返 1004；软删。
- [ ] `PlanUpdate`：改 slots 只重建"今天未到点"的行，taken/missed/skipped 不动；1 药品唯一计划（重复返回冲突）。
- [ ] `ScheduleToday`：rows 逐字字段齐全；顶层 recentView；elder 只返回自己绑定患者。
- [ ] `AdUnlock`：幂等 + 防重放（唯一键 + 30s 窗 + 每场景日上限）；权益存后端。
- [ ] `AssertMember`：非成员 1002 / 权限不足 1003 / elder 越患者 1003，且写审计。
- [ ] 全部读接口 out 带 `server_ts`。

**Integration（真实 PG）**
- [ ] `V001–V003` 脚本可从头重建 schema；账本 append-only + 校验和防篡改（改已执行脚本→拒绝）。
- [ ] `dose_logs` 唯一主键：materializer 重跑 `ON CONFLICT DO NOTHING` 不产生重复行。
- [ ] 并发 CAS：两线程抢同一 `push_task`，只有一个 `ExecuteUpdateAsync==1`。
- [ ] `dose_id` 确定性：同 pid/date/slot 两次生成命中同一行。
- [ ] 漏服兜底 CAS：`alert_status 0→1` 只通知一次。
- [ ] API 端到端：`POST /api/checkin/submit` 返回封套与冻结字段。

### 10.4 TDD 落地节奏（对齐六周路线）
每个用户故事按"写失败测试 → 最小实现 → 重构 → 集成测试"循环。W1 先把 Domain 状态机与 `BjDate` 测通（时区是这个产品的历史坑），再动任何 API。**没有测试的实现不合并。**

## 十一、成本重算（云开发的"31 元/月"要改）

| 阶段 | 旧（云开发） | 新（自建） |
|---|---|---|
| **开发期（W1–W4）** | 云环境免费额度内 ~0 元 | **本机 Docker `medbox`，0 元**（已就绪） |
| **上线（DAU<1000）** | 20–31 元/月 | 轻量应用服务器 2C2G 约 60–100 元/月 + 域名 ~5 元/月 + HTTPS 免费证书 + **ICP 备案 2–3 周（必须提前）** |
| **DAU 1 万** | ~20–50 元/月 | 2C4G 约 150–200 元/月（含 PG 同机或托管）；对象存储/CDN 另计（照片压缩 ≤60KB 纪律不变，否则账单翻几倍） |
| **运维** | ~0 | 自己管补丁/备份/监控（单人节奏下的真实成本是**时间**） |

**结论**：开发期 0 成本不变；上线固定成本从 ~31 元/月升到 ~100 元/月量级，DAU 1 万时约 150–200 元/月。相对 DAU 1 万时 9,000–11,500 元/月广告收入，成本仍不是变量。**但 ICP 备案是新增的关键路径依赖，W1 必须并行启动**，否则上线会被卡 2–3 周 —— 这是云开发"免备案"优势消失后最容易漏掉的一步（已同步到 `00-总方案.md` 的 W1/开工清单）。

## 十二、部署与运维

- **本地开发**：`docker exec` 复用 `tigerrag-postgres-1` 的 `medbox` 库；API `dotnet run`；`JWT__Secret` 用 user-secrets；微信接口用测试号/沙箱或配置 appid。
- **图片存储**：P0 药盒照/头像用对象存储（本机已有 MinIO 可复用，或生产用 COS），签名 URL 访问；**压缩 ≤60KB 纪律不变**。迁移自云存储 fileID 的部分需做一次性映射脚本（P1）。
- **生产部署**：单台 2C2G 起 API + PG（同机或分离）；Nginx 反代 + HTTPS；`systemd`/容器托管；每日 `pg_dump` 备份；健康检查 `/health`。
- **监控**：结构化日志（Serilog）；关键指标——tick 耗时、push 成功率、漏服兜底命中、越权次数、`schema_migrations` 版本一致性。
- **水平扩展**：无状态 JWT + PG advisory lock + `FOR UPDATE SKIP LOCKED` 队列，支持多实例；扩展时 access_token 中控与 worker 分片需复查锁竞争。
