## 一、框架选型结论（v1.2 迁移，不骑墙）

### 1.0 主框架：原生小程序，不跨端

**微信原生小程序 + TypeScript（仅 tsc 编译）+ 自研 60 行 store + 自建 .NET 10 HTTP 后端。不引入 uni-app / Taro / 任何跨端框架。**

| 维度 | 原生 | uni-app / Taro | 判定 |
|---|---|---|---|
| 包体积（老人机启动瓶颈在 JS 解析） | 基线 | +180~500KB runtime | 原生胜 |
| 广告组件 | `<ad>`/`ad-custom` 直用、`createRewardedVideoAd` 原生 | 需条件编译/native 桥，激励视频包裹易出坑 | **原生胜（决定性）** |
| 订阅消息 | `requestSubscribeMessage` 原生 TAP 上下文不丢 | 走 native 层，TAP 上下文易失效 → 直接 fail | 原生胜 |
| 构建链 / 单人维护 | tsc + 一次「构建 npm」 | webpack/HBuilderX + 版本坑 | 原生胜 |
| 只做微信一端 | 无跨端成本 | 跨端收益为 0 成本照付 | 原生胜 |

**网络层**：弃用 `wx.cloud.callFunction` / `wx.cloud.database()`，改为统一 `utils/request.js` 走 `wx.request` + JWT（`Authorization: Bearer`），详见 §6.0。业务契约（11 域 / 字段 / 错误码 / `server_ts`）**逐字不动**，只换传输载体。

### 1.1 UI 框架决策（主理人 2026-10-29 授权"自行决定并锁定版本"）

原 v1.1 终裁"零第三方 UI 库"。本次基于项目真实约束**改为分层决策**，两套并行、各自有理由——这是双端双模在 UI 框架层的延续，不是妥协：

| 端 / 页面 | UI 框架 | 版本 | 理由 |
|---|---|---|---|
| **老人端全部 + 主包 4 tab + 打卡页**<br/>(E10/E11/E12 / P10/P20/P30/P40 / P11+P12 / P42) | **自研组件**（继续用 `UI-设计规范.md` 的 Design Token 与 19 个组件清单），**零第三方 UI 库** | 随 `UI-设计规范.md` 演进，无独立 npm 版本 | ① 老人端字号/热区/四态三重编码由 Token 完全自控，引第三方等于把适老化标准交给别人默认值；② 打卡页是全产品生死页、订阅消息直达，主包预算 < 1MB 且禁 npm 包依赖；③ 老人机 2GB 档，JS 解析越少越好 |
| **子女端分包管理页**<br/>(`packageManage` 表单 / `packageSettings` / `packageReport`) | **TDesign MiniProgram**（腾讯官方），按需引入 `t-field/t-picker/t-stepper/t-dialog/t-toast/t-swipe-cell` 等 | **`1.17.0`**（精确锁定，不用 `^`） | 子女端是多步表单 + 选择器 + 列表管理的**信息密集页**，自研这些控件性价比低；放**分包**按需加载，不占主包预算；TDesign 官方维护、与微信生态一致、支持按需构建 |

**为什么这样分而不是全用或全不用**：
- **全用第三方**：老人端大字（38px 药名、160rpx 主按钮）和四态三重编码会被组件默认样式污染，适老化红线失守，且主包体积破线。**这条不能让步。**
- **全自研**：子女端三步表单的 picker/数字输入/校验状态重复造轮子，且这部分对包体积不敏感（在分包）。**这部分的自研收益不足以抵消工期。**
- **裁决**：以"是否老人可见 / 是否在主包"为界，一条清晰的线，工程上不打架。老人端组件与子女端 TDesign 组件**不互相嵌套**。

**版本锁定（TDD/CI 校验 lock 文件，禁止浮动）**：

| 依赖 | 锁定版本 | 说明 |
|---|---|---|
| `tdesign-miniprogram` | **1.17.0** | 仅子女端分包引用；开发者工具「构建 npm」生成 `miniprogram_npm/` |
| `typescript` | **5.9.3** | **不升 7.x**：`miniprogram-api-typings` 与小程序 tsc 链对 5.x 验证充分，TS 7.0.2 为 Go 重写版，单人项目不冒这个险 |
| `miniprogram-api-typings` | **5.2.3** | 小程序 API 类型声明 |

> 子女端分包引用 TDesign 时，仍须遵守 §5.1 的 Token 覆写纪律：组件内 `font-size` 一律走 CSS 变量，禁止写死 rpx。TDesign 自带主题变量需在 `app.wxss` 对齐到本产品 Token，避免两套蓝。

```json
{ "pages": ["pages/home/index","pages/medicine/index","pages/weekly/index","pages/profile/index",
            "pages/checkin/index","pages/launch/index","pages/legal/index"],
  "subPackages": [
    {"root":"packageManage","pages":["pages/medicine-form/index","pages/medicine-detail/index","pages/patient/index","pages/family/index","pages/plan-form/index"]},
    {"root":"packageReport","pages":["pages/report-detail/index","pages/history/index"]},
    {"root":"packageSettings","pages":["pages/settings/index","pages/unlocks/index","pages/about/index"]}],
  "tabBar": { "custom": true, "list": [
    {"pagePath":"pages/home/index"},{"pagePath":"pages/medicine/index"},
    {"pagePath":"pages/weekly/index"},{"pagePath":"pages/profile/index"}] },
  "preloadRule": { "pages/home/index": {"network":"wifi","packages":["packageManage"]},
                   "pages/weekly/index": {"network":"all","packages":["packageReport"]} },
  "lazyCodeLoading": "requiredComponents", "style": "v2", "pageOrientation": "portrait" }
```

- **`tabBar.custom: true` 的理由**（对 UI 建议 `wx.hideTabBar` 的修正）：原生 tabBar 用 `hideTabBar` 会"先出现再消失"闪一下，老人看到会去点，点进药品管理就迷路。自绘 tabBar 在 elder 模式下**根本不渲染**，零闪烁。代价是 4 个 tab 页各自维护选中态（标准写法，约 80 行）。
- **自绘 tabBar 的三条硬规格**（UI v1.1 要求，易漏）：① 高度固定 **98rpx**、4 tab、每 tab 热区 ≥88rpx；② 4 个 tab 页的滚动容器一律 `padding-bottom: calc(98rpx + env(safe-area-inset-bottom))`，否则列表最后一条被 tab 挡住（子女端列表长，最容易漏）；③ 老人端不渲染 tabBar，但页面底部**必须保留** `env(safe-area-inset-bottom)` padding，否则 160rpx 主按钮会贴住 home indicator；④ 广告位 B 在列表末尾，需额外预留 tabBar 高度，否则老人点广告会点成切 tab。
- **本地资源 ≤ 60KB**：图标用 base64 data-url（小程序不支持 `<svg>` 标签）或 CSS 绘制；空态插画、状态图标、头像、分享图走**对象存储签名 URL**（后端 `IObjectStorage`，见后端方案 §十二）。**药盒照上传前压缩 ≤60KB**（成本纪律不变）。
- npm 包**仅限** `tdesign-miniprogram@1.17.0`（子女端分包），主包与老人端仍是零 npm 依赖。
- 预算：主包 ≤ 800KB，分包各 ≤ 500KB，总包 ≤ 2.5MB。引入 TDesign 后须用开发者工具实测分包体积，超限则减组件。

## 五、状态管理

### 5.1 双模 Token 落地（对 UI §11.1 的技术修正）

**`page[data-mode="elder"]` 不可行** —— `page` 是框架层节点，WXML 里无法给它绑定 `data-*` 属性，该选择器永不命中。三条正确做法同时用：

1. **变量定义在 `page` + 覆写挂根 view**：`app.wxss` 里 `page{--fs-body:28rpx; ...}` 提供 guardian 默认值（page 上的变量会被所有子节点继承），elder 覆写写在 `.p-root.elder{--fs-body:40rpx; ...}`，页面根节点写 `<view class="p-root {{mode==='elder'?'elder':''}}">`。切模式只 setData 一个字段。
2. **page 背景色用 API**（变量改不到 page）：老人端纯白全屏，用 `wx.setBackgroundColor({backgroundColor:'#FFFFFF', backgroundColorTop:'#FFFFFF', backgroundColorBottom:'#FFFFFF'})` + `wx.setNavigationBarColor({frontColor:'#000000',backgroundColor:'#FFFFFF'})`。
3. **禁令 + 两道 CI**：页面 WXSS 内**禁止出现任何写死字号/热区高度**，一律 `font-size: var(--fs-body)`、`height: var(--h-main-btn)`。
   - CI-1 `grep -rn "font-size: *[0-9]\+rpx" pages/` 必须为空；
   - CI-2 `grep -rL 'p-root' pages/**/*.wxml` 必须为空 —— **这条比 CI-1 更容易漏**：fixed 弹层（订阅引导卡、`UnlockNudge`、`ShareCta`、自绘 ActionSheet、`AdSlot`、`DisclaimModal`、`share-toast`）**共七个**，只要有一个落在 `.p-root` 外面，就会静默掉回子女端 12px 字号，且是偶发、极难复现。所有浮层必须挂在 `.p-root` 内部，靠 `position:fixed` 定位而非提到根节点外。

`--st-taken/--st-pending/--st-missed/--st-skipped` 与后端枚举同名，组件内直接 `var(--st-{{status}})`，零映射层。

### 5.2 store 结构

```js

{ openid, serverTimeOffset, mode:'guardian'|'elder', disclaimerAgreed,
  fontSizeSetting:16, reduceMotion:false,
  subState:{ CHECKIN:{quota:0,alwaysAccept:false,mainSwitch:true},
             MISSED:{...}, WEEKLY:{...} },        // alwaysAccept = 已缓存"总是保持"
  entitlement:{ memberLevel:'free', limits:{medicine:3,patient:1} } }  // limits 来自 user.login 的 config，不硬编码
// family
{ families:[{family_id,name,role}], curFamilyId,
  patients:[{patient_id,name,alias,selfOpenid}], members:[{openid,nick,role}] }
// today  ← 打卡页与看板唯一数据源
{ date:'2026-01-20', lastSyncAt, dirty,
  rows:[{dose_id, patient_id, medicine_name, dose_text,          // dose_text 由后端格式化，前端禁做中文映射
         due_minute, due_time, due_ts, status, is_late, taken_at, is_corrected, syncing:false}],
  batch:null }                                              // 推送合并批次
// ad
{ dayCN, aCount, bCount, cAt, cCount, dCount, elderCAllowed:false }
```

持久化：`today`/`ad`/`subState` 落 storage（key 带 `version.js` 版本号，变更即丢弃重拉）；**`entitlement` 与 `quota` 展示值仅作 UI 兜底，真实以服务端为准**（后端每次校验，本地被改不影响）。页面 `onLoad` 里 `this._off = store.sub(...)` 只 setData 变化路径，`onUnload` 调 `this._off()`。禁止页面直接改 store.state。

### 6.0 请求层 `utils/request.js`（替代 cloud.js）

```js
// utils/request.js —— 统一 wx.request + JWT + 错误码拦截
import { API_BASE_URL } from '../config/index'
import { getToken, refreshToken } from './auth'

let retried = false
export async function call(domain, action, data = {}, { method = 'POST' } = {}) {
  const url = `${API_BASE_URL}/api/${domain}/${action}`
  const doRequest = () => new Promise((resolve, reject) => {
    wx.request({
      url, method, timeout: 15000,
      header: { 'Authorization': `Bearer ${getToken() || ''}`, 'content-type': 'application/json' },
      data: method === 'GET' ? undefined : data,
      success: (r) => resolve(r.data),
      fail: reject
    })
  })
  const env = await doRequest()
  if (env.code === 0) return env.data
  // 1001 静默续期后重放一次；打卡链路不阻塞（离线队列兜底，见 §11.2）
  if (env.code === 1001 && !retried) {
    retried = true
    try { await refreshToken(); retried = false; return await call(domain, action, data, { method }) }
    catch { retried = false }
  }
  handleError(env.code, env.msg)
  throw { code: env.code, msg: env.msg }
}

function handleError(code, msg) {
  if (code === 1002 || code === 1003) { wx.reLaunch({ url: '/pages/home/index' }); wx.showToast({ title: '请重新进入', icon: 'none' }) }
  else if (code === 1004)            { /* emit → 弹 UnlockNudge：仅「看视频」+ 关闭，无付费出口 */ }
  else if (code === 1005)            { wx.showToast({ title: msg || '填写有误', icon: 'none' }) }
  else                                { /* 1009/网络失败：写操作入离线队列，读操作重试 1 次 */ }
}
// 便捷别名：call('notify','ack',{...})  ← 字段与冻结表完全一致
```

**要点**：① 前端**永不传 openid**（沿用铁律），身份只从 JWT 取；② `server_ts` 由中间件注入每个读响应，前端算 `offset = server_ts - Date.now()` 做东八区兜底；③ 15s 超时不变；④ 所有写操作幂等重投友好（离线队列见 §11.2）。

| `ad` `unlock` | 激励视频播完 | `{product_id, ad_trace}` → 幂等；权益存后端，前端只渲染 `granted`，本地不留权益 |
| `report` `batch` | 埋点攒批 | `{events:[]}`，**10 条或 5 秒一次**，禁止每次曝光一个请求 |
| `config` `get` | 冷启后异步 | 覆盖 `login` 缓存里可能过期的 `config`（广告开关要能不发版生效） |

**`snooze`（稍后提醒 15 分钟）四态规则 —— 主理人定稿，前端按此实现（§14 C6 终裁）**：
1. **续订 + 延后同一 TAP**：snooze 回调内同一调用栈**先** `silentRenew('CHECKIN')`（§11.1，仅 S2 静默生效）→ **再**调 `checkin.snooze`。**保留真实推送**，不做"只记状态不推送"的降级。
2. **额度为 0 时绝不静默**：续订被拒/失败 → 原地把打卡页切成**大字倒计时卡片**（「还有 14:32 提醒你吃药」，纯 CSS 倒计时，不轮询后端），该条同时在看板顶部**置顶高亮**，直到下次打开或完成打卡。铁律：**绝不允许"点了稍后但什么都没发生"**——老人会判定为坏了。
3. **snooze 不延长漏服判定窗口（主理人终裁：`slot + 60` 固定）**：`due_ts` 只挪一次 15 分钟、`snooze_count` 上限 2；漏服判定基准恒为**原始 slot + 60min**，不因 snooze 移动。
3.1 **snooze 可点窗口 = `slot` ~ `slot + 45min`（`config.snoozeDeadlineMin`）**：超过 45 分钟**按钮置灰**并提示「快到这个点最后时间了，先记一下或者跳过」。原因：若在 `slot+50` 还能 snooze，推送会挪到 `slot+65`，而漏服在 `slot+60` 就触发 —— **推送还没响，系统先判漏服并通知子女**，产品上荒谬。45 分钟窗口保证「延后 15 分钟仍落在 60 分钟窗口内」，同时不延长漏服窗口。
3.2 `missedThresholdMin=60` / `snoozeDeadlineMin=45` 由 `config` 下发，**前端只读不算**。
4. `snooze_count` 以**后端返回**为准，前端不自累加；达上限后「稍后提醒」按钮置灰并提示"已延后 2 次，请选择服用或跳过"。

> **漏服判定前端纪律（必须守住，否则两端显示会打架）**：**前端永不自己计算"是否漏服"**，一律只渲染后端下发的 `status`。本地仅做一件事——把"`server_ts+offset − due_ts > 60min` 且 `status==='pending'`"的项**提前给大字提示**（不改状态、不写库）。**禁止用 `due_ts+15min` 重算漏服时点**（那是 snooze 后的提醒时点，不是漏服时点）。阈值 60min 从 `config` 读，不写死。

**`today_index` / `today_total` 单一 selector 纪律**：打卡页「第 2 次 · 共 3 次」与看板进度**必须来自同一字段**（`schedule.today` 返回，看板用同名同义值），**禁止两页各算各的** —— 否则老人发现两页数字不一致，直接摧毁信任。

**三条日期/时间纪律**：
1. **传日期一律东八区 `YYYY-MM-DD` 字符串，禁止 `new Date().toISOString().slice(0,10)`**（那是 UTC，东八区 08:00 前会算成前一天）。工具函数见 §11.2。
2. **打卡时间戳由服务端取**，前端不传 `clientTs` 作为判定依据（仅可传审计用，后端可忽略）。
3. 判断"是否已过时间点未打卡"用 `server_ts + offset`，老人机本地时间常被改错。

**权限边界（v1.2 改）**：自建后端后**前端无任何数据库直读能力**——所有数据经 `utils/request.js` 走 HTTP，服务端 `assertMember` 统一鉴权。常用药预设的快捷 chip 改为 `GET /api/medicine/common`（公开只读端点，读 `medicines_common` 表，仍免登但走同一请求层）；**v1.5 起 P22 的 chips 与药名联想统一改走 `GET /api/medicine/suggest?fid=&q=`**（`q` 为空 = 全平台引用次数 Top5，计数在 `medicine_usage_stats`：加一次 +1、删一次 −1；`q` 非空 = 本家庭历史 → 全平台榜 → 平台预设），`common` 保留给未升级的旧版本；其余全部需 JWT。这比云开发的"集合级权限"更严：越权判断只有 `assertMember` 一处代码。

**已于本轮闭环的 3 项**：① 批量打卡**不新增 `take_batch`** —— `checkin.submit{items:[]}` 天生批量，能力等价、不是降级，主理人的三条边界（幂等键/部分成功合法/上限 8 条）全部施加在 `submit` 上；② `config` 广告开关已加，**统一 camelCase**，snake_case 那套作废；③ `family.join` 已支持 `role`，但请注意上面的 `role==='elder'` 判定纪律。

**仍需后端补的 1 项**：`checkin.correct`（UI v1.2 §7.4「打卡记录可信度」的硬依赖，现契约里没有）。要求：只允许 `taken → missed/skipped` 单向、不可逆、服务端强校验、留审计（操作人/原状态/时间）；`schedule.today` 出参需带 `is_corrected`（行尾「已修改」灰字用）与 `manualCorrectCount`（周报单列，**不计入完成率** —— 否则子女误操作会污染用药史，而用药史是本产品唯一沉淀的资产）。

**剂量结构（主理人终裁，破坏性变更，types 定稿前必须落）**：原"一药品一单次剂量 + 多时间点"表达不了"早 1 片、晚半片"（缓释片/优甲乐/华法林极普遍）。最终口径：
```js
// plans.slots —— 每个时间点自带剂量与稳定 key
{ medicine_id, cycle_type: 'long_term',
  slots: [ { t:'08:00', d:'1片', slot_key:'s0800' },
           { t:'20:00', d:'0.5片', slot_key:'s2000' } ] }
// medicine.default_dose 保留：新增药品时各 slot 的 d 默认继承它
// schedule.today 每条 dose 带已格式化的 dose_text（"1片"/"半片"），前端直接渲染
```
四条纪律：① **不做"是否不同剂量"开关**，默认填 `default_dose`，子女不改就是统一剂量。② **禁止在前端 JS 或 WXML 里做剂量中文映射**（"半片"这类规则由后端统一出，两端各写一遍必然不一致）—— 打卡卡片显示剂量只读 `dose_text`，**不读药品默认剂量**。③ `dose_logs._id` 规则不变（`{plan_id}_{date}_{minutes}`），`checkin.submit` 幂等键同步不变。④ 三步表单结构不变，仅 **Step3 每个时间点行右侧多一个剂量输入框**（预填 `default_dose`），需验证该行**不撑高表单、不触发键盘遮挡**（两端都测）。

**`checkin.submit` 可选返回 `quota`**：`{CHECKIN,MISSED,WEEKLY}`。**采纳**——打卡成功后本就要刷新额度提示条，带回来省一次 `notify.quota`。注意"首屏 2 请求"只约束**首屏**，不约束交互后的写操作。

## 七、核心页面技术要点

### 7.0 免责告知（**终版 V5：落地页零弹窗 → 点按钮后确认 → 确认才 join**）

**判据只有一条：URL 里有没有 `fid` + `ivt`。** 有 → 按钮后弹；没有（搜一搜/首页/扫码）→ 首屏弹。

**主路径（`from=checkin&fid=&ivt=`，分享卡进来）**
1. **落地页首屏零弹窗**：内容 + 两个按钮 + **底部常驻 `DisclaimerBar`**。
2. 点「我自己吃药」/「我帮家人看着」→ **弹 `DisclaimModal`**（1.2s 置灰、2 行 ≤40 字、单按钮「我知道了」、无关闭叉）→ **确认后才发 `family.join`**。
3. 未确认前：**不发请求、不显示分享按钮、返回不可绕过**。
4. **留痕绑 `openid + family_id`**，写 `disclaimer_ack_at` —— 出事时可证明"他在加入这个家庭组之前被告知过"，比只绑 openid 多一个关系维度。

**例外路径（无 `fid/ivt`：搜一搜 / 首页 / 扫码）**：`P00` **首屏即弹**，用**子女规格**（此时 `mode` 未定、默认 guardian），确认后**分两支**（不分支会现场翻车）：
- **已有家庭组 + 今日有 pending 剂量** → 直达打卡页；
- **无家庭组/无待打卡** → 进 **P42 落地页**，**不是打卡页**。

原因：分享卡进来的新用户**还不是这个家庭的成员**，把他直接扔进打卡页只会看到空态（没药、没服药人），比多走一步 P42 更糟，他大概会直接退出。判据：`fid` 存在 + `today` 有 `status==='pending'` 的行，两个都满足才直达。
审核员走的正是这条路径，前置告知不能削弱。

**`DisclaimModal` 规格取哪一档 —— 跟着"他刚点的那个按钮"走**
- P00 首屏弹 → **子女规格**（标题 36rpx / 正文 28rpx / 按钮 96rpx）；
- P42 点「我自己吃药」→ **老人规格**（标题 48rpx / 正文 40rpx / 按钮 112rpx）；
- P42 点「我帮家人看着」→ **子女规格**。
这样子女第一次看到的东西不会比后面所有页面大一号 —— 规格跟选择走，不跟页面走。

**`DisclaimModal` 规格**：宽 = 屏宽 − 96rpx 居中、`radius-xl` 32rpx、白底 `shadow-2`、**无右上角关闭叉、单出口、无"以后再说"**；标题「仅提供提醒服务」；正文「本工具仅提供服药提醒服务，不提供任何医疗建议，用药请遵医嘱。」色 `#414D5A`、行高 1.6；**1.2s 内按钮置灰 `#C7CFD8` 不可点，且不显示倒计时数字**（老人看到 3…2…1 会更想等，反而更慢）。弹窗背后页面**压暗 40% 黑而非纯黑** —— 保留"爸吃了药"这个说服他的上下文，减少被拦住的感觉。

**`DisclaimerBar` 规格（落两处：P42 落地页底部【主】+ 设置页【长期查阅】）**
- **P10 / E10 首页都不放，打卡页也不放**：主路径的"告知"已由落地页承担，首页再放一遍是重复；"想查时查得到"由设置页满足；打卡页是唯一零噪声页（4 元素、无 tabBar、无广告），且"不提供医疗建议"天天悬在药名上方，老人会读成"这软件说自己不靠谱"。
- 子女端：高 56rpx / 字 24rpx / `#5C6B7A` on `#F4F6F8` / 内距 32rpx / 单行省略（全文在设置页可读）。
- 老人端：高 72rpx（落地页版**自然高度、最小 72rpx、最大 120rpx**，允许 2 行）/ 字 36rpx / `#414D5A`（7.4:1）/ 内距 40rpx。
- 定位：**不可关闭、随内容滚动、不吸顶、无图标**。**禁用**：红/橙警示色、⚠ 图标、关闭叉、任何闪烁。
- 它的存在就是"告知"的**持续证明**：弹窗是一次性的，提示条是长期的。

**`first_checkin_at` 单独记录**，只作"真实使用行为"佐证，**绝不得替代 `disclaimer_ack_at`**（两字段用途不同，合并才会重新出现"子女无留痕"的洞）。

**通用规则（跨模块保留）**：**任何辅助性写入失败，都不得回滚主链路（打卡）的成功状态。** 打卡数据真实性优先于任何附属记录的完整性。

配套埋点：`disclaimer_shown` / `disclaimer_ack`（带 `delay_ms`、`from`、`role`、**`trigger:'first_screen'|'after_btn'`**）。
- 按 `role` 拆看 `ack/shown`：**子女端 < 95% 说明确认框在某条路径上又被跳过**（子女从不打卡，这是最容易漏的一类）。
- 按 `delay_ms` 分桶：**大量点击堆在 1.2s 边界 = 用户在等按钮变亮而不是在读字，说明 1.2s 太短，要上调**。一个设计参数配上能证伪它的埋点，才不是拍脑袋。

### 7.1 打卡页（P11 + P12 同页两态）★ 生死页
**为什么不拆两页**：UI 的动效是从"按钮收缩"连续过渡到"绿环绘制"（§7.2 分层 1.2s），跨页跳转会把动效切断并白屏一帧。所以 **`pages/checkin` 一个 page、`state: 'pending'|'taken'` 两个视图态**，视觉 100% 按 UI 稿实现，P12 是它的第二态。

- **冷启动 ≤1.2s**：`onLoad` **同步**读 `next_dose` 缓存直出待服卡片（onLoad 里 `wx.getStorageSync` 是同步的，无 await 阻塞），`schedule.today` 放到 `onReady` 之后发起；有缓存时**不显示骨架屏**（避免闪烁）。老人从服务通知点开是冷启动，这是全产品唯一必须打赢的性能指标。
- **可点元素配额**（UI v1.1/v1.3，**口径 = 常态可点元素；失败重试属异常态不计入**）：打卡页 **4 个**（主按钮、稍后提醒、今天不吃、齿轮）；P12 **子女端常态 3 个**（返回今日、撤销、分享）/ 异常态 4 个；**老人端常态 2 个**（返回今日、分享）/ 异常态 3 个，**无撤销、无返回箭头等任何导航控件**。验收单按此口径写，避免「规范说 2 个怎么实现 3 个」的扯皮。**成功态绝不出现返回箭头等任何导航控件** —— 老人从订阅消息进来时没有"上一页"概念，给他箭头他就会点出去。
- **撤销：分端差异化**（§14 冲突 C2 定稿）。子女端 P12 保留 3 秒撤销，规格钉死：40rpx 文字按钮、色 `#8A94A0`（弱化，不与「返回今日」竞争）、放副文案下方（屏幕中上部，与页底广告 A 不重叠）、点击后回到 `pending` 态 + toast「已撤销，请重新打卡」、**不做二次确认**（撤销本身可恢复，加确认就抵消防误触价值）。**老人端 P12 不提供撤销**：老人误触撤销的概率高于误打错卡的概率；老人端纠错权交给子女 —— 看板每行右侧「⋯」**可点按钮**（不用长按，长按违反 UI 无障碍第 6 条）可把「已服」改为「漏服/跳过」，改动走 `checkin.correct` 并留审计。
- **打卡流程不得被登录态阻塞**（UI 放行 checkin 进主包的交换条件）：登录过期时仍必须能用本地缓存 `next_dose` 完成打卡，续期在后台静默做，成功后再 flush 队列。**老人点开发现"要重新登录"是致命的** —— 这条优先于任何请求纪律。同理 `checkin` 页**禁止 import 任何重依赖**（图表库 / dayjs / moment / 富文本），首屏只依赖本地缓存 + 一个轻接口。
- **不发包体积警告的页面**：`checkin` 的 WXML 内联成功动效用纯 CSS 关键帧（≤3KB），不得引入图片序列或 canvas。
- **防误触三重**：位移 >24px（滑屏）或长按 >1500ms 直接丢弃点击；主按钮 160rpx 高、全宽 −80rpx、落在 y≈560–720pt；`taken` 态下按钮整体置灰不可重入（`disabled` + `pointer-events:none`）。
- **乐观更新（主按钮永不做 loading）**：点击瞬间 `status='taken', syncing=true` → 按钮**直接进入终态「✓ 已服用」并锁死**（这是防连点，不是等网络）→ 立刻切 `taken` 视图态启动动效。**永不出现"提交中"loading、转圈、全屏遮罩**。所有未同步信息只放顶部细条（见下条）。
- **「已点击但未同步」= 顶部细条唯一表达**（定稿视觉规则，不得自行改动）：`position:fixed` 于导航栏下，高 **64rpx**，顶部吃 safe-area；父容器预留同高占位，**下方内容不得跳动**。三态：① 发送中 `#FF8A3D` 琥珀底白字「正在发送给家人…」② 成功 → 300ms 淡出，**不加 toast/弹窗** ③ 失败 `#C25E17` 深琥珀「网络不好，已记在本机，会自动重试」+ 右侧重试按钮（**104rpx 独立热区**）。**不弹窗、不阻断、状态不回退**（已服终态保持），老人端禁用"失败/错误/异常"字样。
- **打卡进度（老人端，改措辞降权重）**：与「早上 8:00」**同一行右对齐**，文案「第 2 次 · 共 3 次」，36rpx / `#414D5A` / 常规字重；**不单独占行，不做进度条、不做圆点串**。措辞必须是"第几次"而非"还剩几次"（前者是方位感，后者是任务压力）。`today_total === 1` 时整行隐藏；本次为当天最后一次时，按钮下方加一行 40rpx「今天最后一次了」。数据取 `today_index/today_total`（§6 单一 selector 纪律）。
- **批量态（后端推送合并）**：`?batch=` 携带多剂量时，卡片内纵向列出药名，主按钮文案改「这些我都吃了」，并**隐藏「稍后提醒」「今天不吃」** → 可点元素降为 2 个（主按钮+齿轮），符合"多一个都不行"的减法原则。提交走 `checkin.submit{items:[]}`（同一个 action，单批上限 8 条）。
- **批量折叠阈值（主理人裁定，必须实现）**：慢病老人同时吃 3–5 种药是常态。`batch ≤ 3` 全量平铺；**`batch > 3` 首屏只显示前 2 项 + 「等 N 种药」，主按钮始终落在首屏可视区、绝不要求滚动** —— 滚动才能看到按钮等于把 5 秒打卡目标摧毁。埋点加 `checkin_scroll`（是否发生滚动），`batch>3` 时滚动率 >30% 说明折叠策略仍不够，需再压。
- **状态机（含补吃，主理人裁定）**：`pending → taken | skipped | missed`；**`missed → taken` 允许且必须走通**。原因：用户主动打开时，前端会把"`server_ts+offset − due_ts > 60min`"的项在本地标 `missed` 并给大字提示，老人看到就去补吃 —— 若后端只收 `pending`，这次补吃会被拒、队列重试 5 次堆成"待同步"，老人以为没记上。**"漏服项仍可打卡"是兜底路径的一部分，不是异常分支**。`taken → missed/skipped` 仅限管理员手动改（§7.2），且不可逆。前端**不为补吃做任何特判**，统一走 `store/today.take()`（内部转 `checkin.submit`，见 §11.2）。
- **P12 新增 `ShareCta`（UI v1.3 定稿，唯一的"老人主动表达"机会）**：成功动效 1200ms 结束后淡入，位置在**副文案下方、广告 A 上方**。规格：描边次按钮 **112rpx**（2rpx `#2E6BE6` 描边 + `#1E4FBF` 文字），文案 **「让家人知道我吃了」**，用 `<button open-type="share">`（走微信转发，**不做截图保存**，老人找不到相册）。老人端文字 44rpx / 图标 56rpx。同时**「返回今日」降级为 88rpx 纯文字按钮** —— 别把分享做成实心主色，老人第一意图是离开。
- **分享与撤销互斥（重要）**：用户 3 秒内点了分享，**撤销入口立刻消失**。已发进家庭群又撤销，是最坏的错乱。
- 老人端本页可点元素：**分享 + 返回 = 2 个**（含失败重试 3 个），≤4 成立；子女端 3 个 + 撤销 4 个。
- 频控：不限分享次数，但**同设备 1 日内最多一次「分享后家人能看到」提示气泡**（`share-toast`，属第七个浮层，必须挂 `.p-root` 内）。
- **绝不能做成"分享得权益"** —— 那是诱导分享，封号级。
- **老人端渲染 `recentView` 一行灰字**（如「女儿昨天看过」）：**只许一行灰字，不做红点、不做弹窗、不做声音** —— 已读回执的价值是「有人在意我」，一旦变成提醒就变成压力。
- **P12 加一行「女儿已经知道了」**（头像点亮之后）：老人打卡后唯一有意义的奖励，比任何勋章都强，且是"家人看见了"的闭环证据。
- **加入后 90 秒内必须有一次真实操作（aha moment）**：`launch` 分发时判断——今日有已过点未打卡 → 直接进打卡页；只有未到点 → E10 顶部一条「明天早上 8 点会响。现在先试一次？」+「试一下」，点后**完整走一遍打卡动效但 `isDemo:true` 不写库、不上报 `checkin_success`**。理由：加入 ≠ 激活，"被邀请→首打卡 ≥70%"靠一个按钮到不了。
- **"今天不吃"**：原生 `wx.showActionSheet`，4 个固定原因（已吃过/不舒服/医生让停/其他），不做输入框（老人免学习成本，UI §5.2 硬约束 4）。

### 7.2 家庭看板（P10 / E10）
- `schedule.today` 一次拿全量（后端有 `daily_board_cache`），**完成率与连续达标由后端算好**，前端模板只写 `{{overview.rate}}`，不在 WXML 写表达式（每次渲染都求值）。
- setData 精度：`this.setData({[`rows[${i}].status`]:'taken'})`，**禁止整树替换**（10KB 载荷在低端机桥接 30~80ms）。
- **顶部放 `DisclaimerBar`**（子女端 P10 独有）：高 56rpx / 字 24rpx / `#5C6B7A` on `#F4F6F8`，紧贴导航栏下、随内容滚动不吸顶、不可关闭、无图标、禁用警示色与 ⚠。**E10 老人端不放**（老人端只在设置页有），因为老人端一屏只有 4 个元素且以药为主。
- **B 位广告永不吸底**（UI 硬约束）：放列表最后一张卡之下，滚动到才有曝光。吸底是老人误触卸载第一原因。
- **漏服强提示**：顶部 96rpx 红条「爸爸今天 8:00 的降压药还没吃」+「去提醒」，点击滚动定位并高亮 1.2s，**不用全屏弹窗**（会让人产生"被追着骂"的负面情绪）。老人端**不显示任何红色漏服**，漏服只有"待服"一种表达。
- 老人端隐藏 tabBar、服药人切换、药品管理入口，只显示"我的今日"，一屏 ≤4 个元素。
- **E10 可点元素钉死为 4 个**（UI v1.2）：①「去打卡」主按钮 ②用药行（点进打卡）③右上齿轮 ④**广告位（独占热区、不与行重叠）**。注意广告也算进 4 里，**不得为了"元素少"把广告做成不可见热区**，那会踩微信广告合规。
- **E10 一律不渲染**：tabBar、服药人切换、连续达标徽标、漏服红条/红底、「⋯」菜单、打卡时间戳、周汇总、任何插屏与激励视频广告。理由：改状态不是"操作"是"判断"，需要判断力，而老人恰恰是最不该承担这个判断的人（他自己就是被判断对象）—— 这是角色分工不是元素预算。
- **验收口径**：微信自带的右上角胶囊（"···"与"关闭"）属框架层、无法移除，**不计入我们的元素数**，避免验收时互相扯皮。
- **`DoseRow` 5 槽位**（UI v1.1 §7.4）：计划时间 · 药名剂量 · 状态徽标 · **打卡时间戳（仅子女端）** · **「⋯」菜单（仅管理员）**。时间戳放徽标下方 24rpx、文案「08:12 打卡」、色 `--text-3`，**占用原本副行槽位，行高仍 112rpx 不变**（E10 老人端 168rpx 也不变）。老人端后两个 slot 一律不渲染（同一组件 + mode 开关）。
- **改状态必须两步，禁止一点就改**：行右侧「⋯」可点按钮（热区 88rpx）→ `wx.showActionSheet`（改为已服 / 改为漏服 / 改为跳过 / 取消）→ **三项改动全部走 `wx.showModal` 二次确认**（UI v1.3 修正：原规范只要求漏服/跳过确认，实际「改为已服」同样要确认 —— **把漏服洗成完成比把已服记成漏服更严重**，前者直接污染北极星指标）→ 才调 `checkin.correct`。理由：子女误操作会污染用药史，而用药史是本产品唯一沉淀的资产。**不用 `bindlongpress`、不用右滑** —— 长按与行点击（进打卡详情）抢事件，且违反"不依赖手势"的无障碍验收。
- **改完之后的三条渲染约束**：① 手动改过的行尾加 20rpx 灰字「已修改」；② 改为漏服/跳过后**不可再改回已服**，`⋯` 菜单对应项**置灰而非隐藏**（置灰才让人看懂为什么不能点）；③ 周报**单列**"手动修改 N 次"，**不并进完成率**。
- **异常时间标注（`--st-warn`，新增语义色 `#C25E17`，不复用 `--st-missed` 红）**：判定 `|taken_at − due_ts| > 120min` 或打卡落在 00:00–05:00（前端由两个 ms 时间戳直接算，不涉时区换算）→ 时间戳转 `#C25E17` + **前置 ⚠ 图标（必须加，不能只靠颜色，否则违反三重编码）**，文案「⚠ 02:41 打卡 · 比计划晚 5 小时」，凌晨场景追加「这个时间不太对，确认一下？」。**整行不做红底** —— 这是"存疑"不是"漏服"，红底会让子女误判。

### 7.3 多步表单（P22–P24，3 分钟目标）
- 三步一页 + `hidden` 切换（不用 `wx:if`：销毁重建会丢输入焦点，低端机键盘抖动）；每步 1 个问题 + 1 个主按钮 + 默认值预填。
- **草稿**：onInput 500ms debounce 写 `draft_medicine_{patient_id}`；onLoad 检测 24h 内草稿 → 顶部提示"继续上次填写？"，**用户点确认才恢复**。提交成功清草稿。
- **Step3 订阅引导卡**（UI §7.1）：保存成功后同页出现底部卡片（非系统弹窗先行），主按钮「开启用药提醒」→ 点击才 `requestSubscribeMessage`。文案必须说出「勾选『总是保持以上选择』以后就不用再点了」——这句是授权率能否过 40% 的决定性文案。
- **改计划后必须整树重拉**：修改时间点会生成新的 `dose_logs._id`（主键含分钟数），旧行若 `pending` 且未到点由后端删除、已 `taken/missed/skipped` 的一律不动。所以**保存计划成功后必须重新拉 `schedule.today`（或 `dose.today`），禁止本地乐观复用旧 `dose_id`** —— 否则老人点下去会拿到 422 / `not_member`，且表现为"点不动"。
- **历史与周报直接渲染快照**：`dose_logs` 存 `dose_text` + `med_name_snapshot`，所以历史页与周报**不 join 药品表**（少一次关联、少一次口径不一致）；药品改名/删 slot 都不影响历史显示。
- **Step3 剂量输入行（新结构配套）**：每个时间点行 `[08:00]  [1 片 ▾]  [删除]`，右侧剂量框预填 `medicine.default_dose`，点击弹 `Chip` 快捷项（半片/1片/2片）+ 自定义输入。三条实现约束：① 该行**不得撑高表单**（固定行高，用行内元素不用纵向堆叠）；② **不得触发键盘遮挡**（`adjust-position` + `cursor-spacing`，且默认不聚焦，老人/子女两端都要真机验证）；③ 不改剂量就不写入 `d`，交给后端继承默认值，减少一次无意义 diff。
- 第 4 个药品：`1004` 拦截 → `UnlockNudge`，**只有两个出口**：「看 15 秒视频，免费再加 1 个」（主）+ 「关闭」（40rpx `#8A94A0` 纯文字、放底角、不用描边按钮样式）。**不得出现"9.9 元/年""家庭版""会员""升级"任何字样与占位图，也不留注释掉的死代码** —— 审核与自查会把它当成未完成功能。只阻断新增，不阻断查看已有。
- **点关闭不清空表单**：draft 必须已落缓存，看完视频回来也还在。用户填到一半被拦本来就烦，清空会直接骂人。
- **视频中途退出（`isEnded:false`）不发名额**：返回表单、保留 draft，给中性提示「视频没看完，名额还没到账」。**不指责、不重复弹窗**。

从「我的」进入，非 tab 页。结构：**概览卡**（累计解锁次数）+ **三组列表**（药品名额 / 周报详情 / 历史数据）+ **列表末尾广告位 B（200rpx）**。全页无价格、无支付入口、无"会员/升级"字样。

- **空态必须有，不能白屏**：320rpx 插画 + 「还没有解锁过东西」+ **列出能解锁的三项** + 主按钮「去看看」跳周报页 —— 形成「空态 → 看视频 → 回来看见」的闭环，空态是转化入口而不是死胡同。
- **空态也放广告 B**：与 §5.1「空态不放广告」不冲突（那条针对的是无数据的功能空页；本页空态本身就是"去解锁"的引导页，广告是列表末尾的自然延伸）。**这条不要再当矛盾改掉。**
- 插画若美术来不及：用图标 + 主色圆形占位，**不要用默认灰块**（灰块等于"加载失败"，用户会退出）。

### 7.6 邀请落地页 P42（裂变第一跳，文案即转化率）

结构（信息密度高但只有 3 个可点元素：主按钮 / 次按钮 / 关闭）：
1. **顶部不要写"女儿邀请你加入"**，改成**"她已经替他做好了"的叙述 + 具体药单**：「女儿已经设好了：早上 8:00 降压药 1 片 / 晚上 8:00 降压药 1 片 / 到点手机会响，响了点下面一下就成。」老人对"加入"是防御的，改成"她已替我做完了"，防御变感谢。
2. **主按钮「我自己吃药」160rpx**，下方灰字「点了就会收到提醒」——**字号 36rpx、色 `#414D5A`**（增长原定 32rpx / `#8A94A0` 已被设计拦下：32rpx≈16px 破老人端 36rpx 下限，`#8A94A0` 白底对比度仅 3.1:1 远低于老人端要求的 ≥7:1）。
3. **次按钮「我帮家人看着」120rpx**（描边加粗 2rpx `--brand-500`，不能压太轻，否则兄弟姐妹误点主按钮进老人模式后再也找不到看板）+ **副标题「家里谁没吃药，你都能看见」（限 1 行）**。副标题必须覆盖"只协同查看、不设提醒"的兄弟姐妹——写"设提醒"会让这批人在点之前就犹豫，而他们恰恰是二次传播的关键节点（**他在点之前就走了，根本没机会迷路**）。
4. **加入后立刻校验 `role`**：必须 `role==='elder'` 才切老人端（`patient` 只是入参意图、不入库）；若返回非 `elder`，用 path 里的 `role=patient` 兜底强制切一次 + 上报 `role_bind_failed`。**这个 bug 不报错、只表现为"老人不用"**，会被误判成留存问题去改产品。
5. 关闭按钮走 `launch` 回到空态首页，不做强制加入。

**整页渲染规格：按"向弱侧倾斜"，直接用老人规格，不做双模**（字号 ≥36rpx、主按钮 160rpx、次按钮 120rpx）。理由：**P42 是唯一不知道来者是老人还是家属的页面**（知道身份就不需要他选了）。身份未知时只能按最脆弱的一方渲染 —— 老人看到大字不损失理解，家属看到大字也不困惑。**别为了复用双模样式给它套两套版式**：双模依赖身份，而身份正是在这一页诞生的。

三条限量（防超屏）：① 药单**最多 2 条 + 「等 N 种药」**（与 §7.1 批量折叠规则一致）；② 副标题与说明灰字**各限 1 行**；③ **一屏装完、不许滚动** —— 老人不会想到往下滑，会以为页面就这些然后退出。**内容超屏时砍药单条数（2→1→0），绝不砍按钮尺寸。**

## 十、提醒落地（前端配合后端定时任务）

1. **养额度**：`CHECKIN` 池靠"打卡回填"日清日结（后端 §6.2 的正循环）。前端负责把它变成零打扰：已勾选"总是保持"的用户，在打卡成功态任意一次 TAP 内**静默**续订（§11.1 S2 分支），老人永远看不到弹窗。
2. **点开即打卡**：推送 `page` 直指 `pages/checkin/index?dose=&batch=`，**直达打卡页而非首页**（少一次点击 = 少一次流失）。合并推送（同分钟多药）→ 打卡页批量态一键全服。
3. **主动打开补拉（额度耗尽的唯一兜底）**：`app.onShow` 与 `home.onShow` 调 `schedule.today`，diff 出"已过点仍 pending"→ 顶部红条（子女端）/ 卡片置顶（老人端）。**本地只给提示、绝不改状态**（`server_ts+offset − due_ts > 60min` 且 `status==='pending'` 时出大字提示，不写库、不标 missed），避免与后端状态闪烁；阈值 60min 从 `config` 读。
4. **优先级**：订阅推送 → 主动补拉 → 子女端看板红点/TabBar badge → 管理员"一键拨号"（后端 L4，`wx.makePhoneCall`，号由管理员自己存）。
5. **不做**：不尝试 `wx.startBackgroundAudio` 等保活（违规且不可靠）、不做本地长定时（切后台即挂起）。

### 11.1 订阅授权四态状态机 `utils/subscribe.js`

```js
import { TMPL_IDS } from '../config/index'
import { call } from './request'
let alwaysCache = {}            // { tmplKey: true } —— 关键：TAP 内不能 await，必须在启动时预热缓存
const ORDER = ['CHECKIN', 'MISSED', 'WEEKLY']      // 与后端 push_tasks.tmpl_key 同名，避免两套字符串互查

/** app.onLaunch 调用：预热 getSetting 结果，避免 TAP 内 await 丢失上下文 */
export async function primeSubscribeState() {
  const s = await new Promise(r => wx.getSetting({ withSubscriptions: true,
    success: r, fail: () => r({}) }))
  const item = (s.subscriptionsSetting && s.subscriptionsSetting.itemSettings) || {}
  alwaysCache = {}
  ORDER.forEach(k => { alwaysCache[k] = item[TMPL_IDS[k]] === 'accept' })  // 'accept' = 已勾选总是保持
  return { mainSwitch: !!(s.subscriptionsSetting || {}).mainSwitch !== false, alwaysCache }
}
export const isAlwaysAccept = (k) => !!alwaysCache[k]

/** 唯一授权入口。必须在用户 TAP 回调里同步调用，一次只申请 1 个模板（合规 8.6） */
export function requestOne(tmplKey, scene) {
  return new Promise((resolve) => {
    const tmplId = TMPL_IDS[tmplKey]
    wx.requestSubscribeMessage({
      tmplIds: [tmplId],
      success(res) {
        const accepted = res[tmplId] === 'accept'
        const ban = res[tmplId] === 'ban'
        report('subscribe_result', { scene, tmpl: tmplKey, accepted, ban })
        if (accepted) alwaysCache[tmplKey] = true              // 勾选过「总是保持」后本地立即生效
        // 无论接受还是拒绝都要上报：拒绝数只有前端知道，不报则授权率永远 100%，PRD 假设2 无法验证
        // 注意：ack 是 fire-and-forget，requestSubscribeMessage 仍在 TAP 同步栈内（见 §16 踩坑）
        call('notify', 'ack', { tmpl_key: tmplKey, accepted: accepted ? [tmplKey] : [], requested: 1 })
          .then(d => resolve({ accepted, needSetting: !accepted && ban, quota: d && d.quota }))
          .catch(() => resolve({ accepted, needSetting: !accepted && ban }))
      },
      fail(err) {
        const off = /ban|20004|auth den/i.test(err.errMsg || '')
        report('subscribe_result', { scene, tmpl: tmplKey, err: off ? 'main_off' : 'fail' })
        resolve({ accepted: false, needSetting: off })
      }
    })
  })
}

/** S2 静默续订：仅当用户已勾选"总是保持"时才在打卡 TAP 内调用 —— 无弹窗，不违反 UI 铁律 */
export function silentRenew(tmplKey) {
  if (!alwaysCache[tmplKey]) return          // 未勾选 → 绝不在此调用，否则弹窗会打断打卡
  wx.requestSubscribeMessage({ tmplIds: [TMPL_IDS[tmplKey]], success: (res) => {
    if (res[TMPL_IDS[tmplKey]] === 'accept')
      call('notify', 'ack', { tmpl_key: tmplKey, accepted: [tmplKey], requested: 1 })
  }, fail: () => {} })
}
```
四态决策表（把三方要求合并成一条可执行规则）：

| 状态 | 判定 | 行为 |
|---|---|---|
| S1 未授权 | `itemSettings` 无该 tmpl | 只在 P24 保存成功 / P41 加入成功 / 周报页出现 `SubscribeCta` 卡片，**用户点按钮才弹窗**，文案强调勾选「总是保持」 |
| S2 已勾选总是保持 | `itemSettings[tmpl] === 'accept'` | 打卡成功态 TAP 内 `silentRenew('CHECKIN')` **静默 +1**，老人零打扰 → 日清日结正循环成立 |
| S3 拒绝且未勾选 | `reject` | 不重复弹窗（UI §7.1 硬约束）；页面内黄条 + 我的页红点未完成项 |
| S4 总开关关闭 | `mainSwitch=false` / `ban` | 引导 `wx.openSetting`，**一次会话只引导一次** |

### 11.2 东八区日期 + 打卡乐观更新 + 离线队列

```js
// utils/time.js —— 禁止用 toISOString().slice(0,10)（UTC，08:00 前会算成昨天）
export const dateCN = (ts = Date.now()) => new Date(ts + 8 * 3600e3).toISOString().slice(0, 10)
export const minuteOfDay = (ts = Date.now()) => { const d = new Date(ts + 8 * 3600e3)
  return d.getUTCHours() * 60 + d.getUTCMinutes() }

// utils/queue.js
import { call } from './request'
const K = 'q_write_v1', MAX = 5
const read = () => wx.getStorageSync(K) || []
const write = q => wx.setStorageSync(K, q)
export function enqueue(t) { const q = read(); q.push(t); write(q); flush() }
export async function flush() {
  const q = read()
  if (!q.length) return
  // 单条与批量走同一个 action：checkin.submit{items:[]}，单批上限 8 条
  const batch = q.slice(0, 8)
  try {
    // call() 已解响应封套，直接拿到 data；1001 静默续期重放由请求层负责
    const d = await call('checkin', 'submit', {
      items: batch.map(t => ({ pid: t.pid, date: t.date, slot: t.slot,
                               status: t.kind === 'take' ? 'taken' : 'skipped',
                               skip_reason: t.reason })) })
    // applied 里 changed:false = 幂等空操作（原本已是该状态），同样出队，重投不会卡住队列
    const done = new Set((d.applied || []).map(a => `${a.pid}_${a.date}_${a.slot}`))
    write(read().filter(t => !done.has(`${t.pid}_${t.date}_${t.slot}`)))
    // rejected 部分成功合法、不整批回滚：仅把这几条留队并提示用户
    if ((d.rejected || []).length) report('checkin_rejected', { n: d.rejected.length,
      code: d.rejected[0].code })
    if (d.quota) store.set({ 'user.subState': mergeQuota(d.quota) })   // 顺手刷新额度提示条
    store.set({ 'today.dirty': read().length > 0 })
  } catch (e) {
    write(read().map(t => ({ ...t, retry: Math.min(t.retry + 1, MAX) })))
    setTimeout(flush, Math.min(1000 * 3 ** q[0].retry, 27000))        // 1s/3s/9s/27s 退避
  }
}
```

## 十六、踩坑记录（上线后极难查，留档）

| 坑 | 现象 | 根因 | 正确做法 |
|---|---|---|---|
| **tabBar 页必须在主包** | 想把打卡页/药品列表下沉分包，编译期报错或 tab 点不开 | 微信规定分包页面不能作为 tabBar 页 | 4 个 tab 只放薄壳，重业务（表单/详情/报告/设置）全下沉；主包实测 ≈250KB 仍远低于 800KB 预算 |
| **`toISOString().slice(0,10)` 取日期** | 东八区早上 8 点前，打卡被记到"昨天"，日完成率算错，跨天时任务列表错乱 | `toISOString()` 返回 UTC，UTC 与东八区差 8 小时 | 统一用 `dateCN()`（`new Date(ts+8*3600e3)` 后取 UTC 字段），全项目禁用裸 `toISOString().slice(0,10)`；lint 规则拦截 |
| **`page[data-mode="elder"]` 切主题** | 双模完全没生效，所有页面都是子女端 12px 字号 | `page` 是框架层节点，WXML 无法给它绑 `data-*`，属性选择器永不命中 | 变量定义在 `page{}` + 根 view class 覆写 + `wx.setBackgroundColor` 改 page 底色；配 CI-2 `grep -rL 'p-root'` 防浮层漏出 |
| **`requestSubscribeMessage` 放在异步回调里** | 授权静默失败，额度永远为 0，推送全部跳过 → 用户"到点没收到提醒" | 该 API 必须由用户 TAP 手势触发，进入 `wx.request`/`callFunction` 等异步回调后再调用必报 `can only be invoked by user TAP gesture`（HTTP 化后此坑依然存在） | 授权调用只能放在 TAP 回调同步栈内；`notify.ack` 上报用 fire-and-forget，不 await；"是否已勾选总是保持"在 `app.onLaunch` 预热缓存，TAP 内只读缓存不 await |
| **`wx.getSystemInfo` 取 `fontSizeSetting`** | 新基础库上报废弃警告，未来版本可能取不到 | API 已废弃拆分 | 用 `wx.getAppBaseInfo().fontSizeSetting`，带 `getSystemInfoSync` 降级 |

---

**选型一句话**：选原生，是因为只有原生能零损耗做对三件事——`requestSubscribeMessage` 的 TAP 上下文、`createRewardedVideoAd` 的单例复用、`<ad>` 的 error 兜底——而这三件正好是"提醒触达率"与"广告填充率"的命门。
**最棘手的问题**：一次性订阅额度 vs "老人每天 3 条提醒"的结构性矛盾。最终解法不是弹窗硬要，而是**四态授权状态机 + 静默续订**：用户勾选"总是保持"后，打卡成功态的任意一次点击就把额度静默 +1（零弹窗、不违反设计铁律），额度池日清日结；未勾选时才用底部卡片显式引导。三方的要求在这一个机制里同时成立。
