## P0-1 漏服行被渲染成「已服」成功页

- **改了什么**：`miniprogram/pages/checkin/index.ts`（`build()` 三分支 + 新增 `onMakeup` + `onTake` 视图锁）、`miniprogram/pages/checkin/index.wxml`（新增 `viewState === 'missed'` 视图）
- **为什么这么改**：原来 `?dose=` 命中的行只要 `status !== 'pending'`，就一律 `list=[hit]; viewState='taken'`，`missed / skipped` 也渲染绿勾「已经记下了」——用户以为补记成功，实际一次都没写。
  现在按 `hit.status` 分三支：`pending` → 打卡视图；`taken` → 成功页；`missed / skipped` → 新增漏服视图（`status-badge` 显示真实状态 + 一句事实说明）。
  补记入口只给契约允许的迁移：走 `checkin.submit(status=taken)`（即 `store/today.ts` 的 `take()`），契约 §7 允许 `missed（系统判定、is_corrected=false）→ taken`，服务端 `DoseTransitions.CanSubmit` 同口径。
  `skipped`（`CanSubmit` 无 `skipped→taken`）与已人工改判的 `missed`（`is_corrected=true`）是终态，只显示说明、不给按钮，且文案直说「按规则不能再改」，不给出不存在的出路。
  同族分支一并收口：`build()` 末尾「无 pending 也无 taken」的兜底原来也硬设 `viewState='taken'`，现已改为按末条真实状态渲染漏服视图（同一 bug 类，同一函数内）。
  未走 `checkin.correct`：该 action 服务端要求 `admin/member`，老人本人调用会被 1003 拒；`submit` 才是本人可用的通道（服务端另有 `IsElder && !SelfUids.Contains(pid)` 兜底）。
- **怎么验证的**：`npx tsc --noEmit -p tsconfig.json` 零报错；人工核对三支分支互斥且 `wx:elif` 链完整（`pending → taken → missed → else`）。
- **commit**：`43e0901`

## P0-2 本人点「我已服用」静默无反应

- **改了什么**：`miniprogram/pages/checkin/index.ts`（`onTake` 过滤条件 + 空列表提示）
- **为什么这么改**：进视图用 `isSelf()`（身份）筛行，`onTake` 却用 `this.data.elder`（字号）再筛一次。默认普通版下 `isSelf()=true` / `elder=false`，`missed` 行被二次筛掉 → `list` 为空 → `return`，按钮点了既无请求也无提示。
  现在过滤条件改用 `isSelf()`，与 `build()` 同源；`list.length === 0` 时 `wx.showToast` 明确告知「这条已经记过了，不用重复点」，禁止静默 return。
  全页复核 `this.data.elder` 剩余 3 处（`take(list, elder ? 0 : 3000)`、`canUndo: !elder`、撤销窗口 `setTimeout`）——判的都是**字号**（子女端才有 3 秒撤销），保持不动。
- **怎么验证的**：`npx tsc --noEmit -p tsconfig.json` 零报错；`grep -n "elder" pages/checkin/index.ts` 确认只剩撤销窗口三处。
- **commit**：`13cc078`

## P0-4 登录态失效无限重登

- **改了什么**：`miniprogram/utils/request.ts`（`CallOptions.replayed` + 1001 分支重写，删除模块级 `retriedOnce`）
- **为什么这么改**：原来 1001 时置 `retriedOnce = true`，重放前又复位 `false`，重放再失败仍满足 `!retriedOnce` → 递归重登无上限，登录接口被打爆、页面卡 loading。
  现在「已重放过」由入参 `opts.replayed` 沿递归传染（重放时 `{ ...opts, replayed: true }`），进 1001 分支先判 `opts.replayed`：是则只提示一次「登录已过期，请重新进入」+ 落 `logClient` warn + 抛 `ApiError(1001)`，不再续期也不再重放。续期本身失败同样不再重试。
  保证「只重放一次」：一次 1001 最多 `refreshSession()` 一次 + 重放一次；`login()` 走裸 `wx.request`、不经过 `call()`，不存在 login→refresh→login 的自激回路。
- **怎么验证的**：`npx tsc --noEmit -p tsconfig.json` 零报错；`grep -rn retriedOnce --include=*.ts` 无残留。
- **commit**：`75f1cf0`

## P0-8 批量打卡撤销丢数据

- **改了什么**：`miniprogram/store/today.ts`（`undoTake` 整批回滚）、`miniprogram/pages/checkin/index.ts`（`onUndo` 传整批）
- **为什么这么改**：原 `undoTake(r)` 一进来 `clearTimeout` + `heldRows=[]`，只 `patchRow(r)` 一条，整批里其余行本地显示已服却永不上行 —— 少记服药且全链路无报错。
  选定方案 = **整批回滚**（而非「批量时不显示撤销」）：撤销窗口本来就是把整批压住不上行，整批回滚语义干净，且不削减现有 UI 能力。
  实现：以 `heldRows`（确切「还没发出去」的集合）为准整批 `patchRow(..., { status:'pending', taken_at:0, syncing:false })`，并**先清空 `heldRows` 再 patch**——即便 patch 过程抛错也不会有残留任务被 `commit()` 误发；`heldRows` 为空时用入参兜底。页面 `onUndo` 改为传 `this._pendingAll` 整批。
  契约依据：撤销只发生在「未上行」窗口内，不产生 `taken→pending` 迁移，因此不触犯「`taken→missed/skipped` 单向、不可逆」。
- **怎么验证的**：`npx tsc --noEmit -p tsconfig.json` 零报错；`grep -rn "undoTake"` 确认唯一调用点已改传整批；`flushHeld()` 在撤销后因 `holdTimer=null` 直接返回，无补发路径。
- **commit**：本条（`fix(store): 批量打卡撤销整批回滚，不再丢记录` 那次提交）
