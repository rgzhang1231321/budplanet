## 二、里程碑备注

### M1 · 设计与契约定稿（2026-10-30）

- **目标**：在写代码之前把"做什么、字段叫什么、错误码怎么回"定死，避免前后端各持一版。
- **交付物**：`docs/` 9 份（00-总方案 / PRD / UI 设计规范 / 前端技术方案 / 后端技术方案 /
  后端云开发方案（历史归档）/ 契约冻结表 / 合规与通知文案 / 增长与变现方案）+ `AGENTS.md` 开发规范。
- **验收标准**：11 个业务域的字段、action 名、错误码、四态枚举、`server_ts` 逐字一致；
  文档间冲突有明确裁决（见 `AGENTS.md` §2.1 的 5 处已确认口径）。
- **备注**：契约表 v1.4 补了 `slot = 当日分钟数 0–1439` 的定义，并把 `${minutes}` 统一为 `${slot}`；
  `dose_id = ${pid}_${date}_${slot}` 是后续所有打卡/改判的主键，不能再变。

### M2 · 数据基线与迁移纪律（2026-10-30）

- **目标**：schema 可被任何人从零重建，且已执行的脚本永不被篡改。
- **交付物**：`db/migrations/V001–V005`、`db/apply.sh`、`db/migrations/README.md`。
  V001 建 19 张业务表（0 外键）、V002 建 26 条索引、V003 种子（`app_config` + 6 个常用药）、
  V004 写三套订阅模板 ID、V005 建 `app_logs`。
- **验收标准**：`bash db/apply.sh` 在空库上顺序跑通；重复执行幂等；
  SHA-256 记入 `schema_migrations`，改历史脚本立即报错中止。
- **备注**：禁用 EF Core Migrations（不用 `dotnet ef` / `Database.Migrate()`），EF 只做映射。
  下一个版本号 = 目录最大号 + 1（当前 `V006`），**数目录，别凭记忆**。

### M3 · 后端 API 与领域模型（2026-10-31）

- **目标**：11 个域全部可用，业务规则可被单测覆盖。
- **交付物**：`server/`（Domain / Application / Infrastructure / Api 四层 +
  Domain.Tests / Application.Tests）+ `server/scripts/smoke.py` / `smoke_v2.py` / `seed_demo.py`。
- **验收标准**：`dotnet test` **111 passed**；冒烟脚本全链路通过；异常统一走
  `ExceptionHandlingMiddleware` → `{code,data,msg}`。
- **备注**：时区一律东八区派生自然日、时刻存 UTC 毫秒；`status` 用 `VARCHAR + CHECK` 四值；
  `assertMember` 放用例第一行，越权写 `audit_logs`。

### M4 · 小程序双端与核心闭环（2026-10-31）

- **目标**：子女设药、老人打卡、家人看见，一条链路端到端跑通。
- **交付物**：`miniprogram/` 17 页 + 14 组件（`page-nav` / `primary-button` / `dose-row` /
  `status-badge` / `ad-slot` …）+ `store/` + `utils/`（request / auth / queue / logger / subscribe）+ mock 后端。
- **验收标准**：`bash miniprogram/scripts/check.sh` 全绿（CI-1..5 + tsc）；
  模拟器内完整走通「双模选择 → 看板 → 打卡 → 周报 → 家庭」。
- **备注**：老人端判定**只用 `mode`**，`role` 只管权限；打卡 3 秒撤销用"暂缓上行"实现
  （契约不允许 `taken → pending`）；离线队列按 `{pid,date,slot}` 去重。

### M5 · 通知推送与后台服务（2026-11-01）

- **目标**：到点能推、漏服能告警、周报能发，且额度（一次性订阅）被正确扣减。
- **交付物**：6 个 BackgroundService（Materializer / ReminderTick / Push / WeekReport /
  Archive / Stats）+ 真实订阅模板 ID + `app_logs` 日志落库（`source=client|server`）+ `server/scripts/logs.sh`。
- **验收标准**：Worker 日志可见「漏服判定 / 提醒入队 / 告警入队 / 周报归档 / 日指标写入」；
  `push_tasks` 按 errcode 判决重试或丢弃；客户端异常可 `SELECT * FROM app_logs` 直接定位。
- **备注**：MISSED 模板**不带药名**（子女手机可能被旁人看到），CHECKIN 模板保留药名；
  额度不足时不入队，只记 `subscriptions` 计数。

### M6 · 真机验收与环境加固（目标 2026-11-08，进行中）

- **目标**：把"模拟器能跑"变成"手机上真能用"。
- **范围**：
  1. 真机「预览」全链路（登录 → 设药 → 打卡 → 家人可见）；
  2. 接口地址按平台派生（devtools `127.0.0.1` / 真机局域网 IP），防火墙放行 5080；
  3. 订阅消息真机实测（当前无 `Wx:AppSecret`，`errcode=-3`，推送只在库里排队）；
  4. 老人端大字号、防误触、弱网/断网表现。
- **验收标准**：手机与电脑同一 Wi-Fi 下，无一条 `request_fail`；三条订阅模板各收到一次真实消息；
  断网时打卡进队列、恢复后自动同步。
- **备注（已完成的加固）**：`config/index.ts` 改为 `apiBase()` 按平台派生 + 支持 storage `api_base` 覆盖；
  `request.ts` 网络失败抛 `ApiError(-1, '连不上服务器（http://…）')`，不再把所有网络问题折叠成"保存失败"；
  本机防火墙已加 `MedBox API 5080 (dev)` 入站规则。

### M7 · 上线发布（目标 2026-11-22）

- **目标**：拿到合法域名 + HTTPS，代码提审通过，第一批真实家庭可用。
- **范围**：ICP 备案（2–3 周关键路径）、域名 + 证书、`API_BASE_URL` 切正式域名、
  类目选「工具-效率」、隐私协议与免责声明在真机勾选留痕、体验版 → 审核 → 发布。
- **验收标准**：`https://<域名>/api/config/get` 返回 200；正式版从微信入口冷启可登录；
  后台能看到真实 `dose_logs` 生成。
- **备注**：备案是硬阻塞，**W1 就要提交**；上线后 `WX__SECRET` 必须走服务器环境变量，
  禁止进仓库（当前 `appsettings.json` 里 `AppSecret` 为空串，是刻意的）。

### M8 · 增长与变现（目标 2026-12-20）

- **目标**：邀请链路跑通，UV 过 1000 后开通流量主并爬坡广告位。
- **范围**：`family.join` 邀请落地页转化、分享卡、`ad-slot` 位序（A → D → B → E → C）、
  解锁（看广告换药品名额）频控、埋点回收（`report.batch` 落 `stats_daily`）。
- **验收标准**：邀请率 ≥ 30%（对照 `<30%` 的止损信号）；广告位上线后留存不崩、eCPM 有数；
  每个设计参数都有一个可证伪的埋点。
- **备注**：`ad.unlock` 已有 30s 窗 + 每场景日上限 5 + `ad_trace` 幂等，改频控走 `app_config`，不要写死常量。

### M9 · 运营与止损评估（目标 2027-01-31）

- **目标**：用数据决定"继续投时间 / 收缩 / 停"。
- **范围**：DAU、次日/7 日留存、家庭数、人均服药人数、广告收入、`missed` 率。
- **验收标准**：对照 `docs/00-总方案.md` 第七节止损线给出结论，并把结论写回本文（不改历史，追加一行结论）。
- **备注**：这是唯一允许"不产出代码"的里程碑，产物是一份数据结论。

## 四、汇总口径（后期汇总照这个来）

1. **一个批次 = 一个里程碑**：commit 标题前缀写模块，正文最后一行写 `[M6]` 这类标记；
   `git log --grep "\[M6\]"` 就能拉出该里程碑的全部改动。
2. **GitHub Issue/PR 必须挂 Milestone**，不挂的视为待归类，周会前清空。
3. **每个里程碑收口时补三行**：已完成 / 未完成（顺延到哪个里程碑）/ 新增风险。
4. **验收证据优先于描述**：贴命令输出（`dotnet test`、`check.sh`、`smoke.py`、SQL 查询结果），
   不写"已实现"这种无法证伪的话。
5. 里程碑不追溯修改历史备注，结论一律**追加**。

## 五、创建 / 同步 GitHub Milestones

```bash
# 1) 准备一个有权限的 token（classic: repo；fine-grained: Issues 读写）
export GH_TOKEN=ghp_xxxxxxxx

# 2) 先看要建什么（不碰远端，无需 token）
python scripts/gh-milestones.py --dry-run

# 3) 真正创建（按标题幂等，已存在的跳过，不会重复）
python scripts/gh-milestones.py
```

脚本读 `scripts/milestones.json`，与本文表格一一对应；改里程碑的顺序是：**先改本文 → 再改 json → 再跑脚本**。

- **已同步**：2026-11-01 建好 #1–#9（M1–M5 关闭态，M6–M9 开启态）。
- **日期口径**：GitHub 的 `due_on` 只存日期，脚本统一用 `T12:00:00Z` 提交 ——
  写 `T00:00:00Z` 会因时区换算在页面上显示成**前一天**（踩过一次）。
