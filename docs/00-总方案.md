> 主理人：商见成 ｜ 团队：微信小程序盈利开发团（设计 / 前端 / 后端 / 增长）
> 本文件是决策层总纲，四份执行文档为其落地细节。**先读这一份，能判断要不要做；要动手再看后面四份。**
> **产品对外名：替你记着吃药**（唯一通过审批的名称）。文档内「小药盒」为历史代号。

> ## 技术栈变更（2026-10-29 主理人决策）
> 后端由**微信云开发**改为**自建 .NET 10 + EF Core + PostgreSQL**（禁 EF 迁移、SQL 脚本顺序递增、复用本机 Docker 但另建 `medbox` 库、**绝不触碰 `ragdb`**）；前端仍为**微信原生小程序**，UI 框架分层并锁版本（老人端自研 + 子女端 TDesign 1.17.0）；后端 **TDD** 开发。技术方案见 `docs/后端技术方案.md`、`docs/前端技术方案.md`。
> **由此产生两个必须知道的变化**：① 开发期数据库 0 元，但**上线需服务器 + 域名 + ICP 备案（2–3 周，W1 必须并行启动）**；② 运行成本从"~31 元/月"重算为"上线 ~100 元/月量级"。详见 §3.1 与 `后端技术方案.md` §十一。

## 一、结论先行

**做「替你记着吃药 · 家庭用药提醒」：子女在微信里给父母设吃药提醒，老人到点收到推送、点一下「我已服用」，子女实时看到今天吃没吃。**

- **启动成本**：0 元现金 + 约 6 周业余时间（你自己写代码）；开发期数据库用本机 Docker，**0 元**
- **运行成本**：开发期 0；**上线基准约 100 元/月量级**（轻量服务器 60–100 + 域名约 5 + 免费 HTTPS）；DAU 1 万时约 150–200 元/月。**照片未压缩仍会让存储/CDN 账单翻几倍，压缩 ≤60KB 铁律不变**
- **新增关键路径**：域名 + **ICP 备案需 2–3 周**，W1 第一天并行启动，否则上线被卡（云开发"免备案"优势已消失）
- **收入真相**：DAU 1 万时月广告收入 **9,000–11,500 元**，DAU 3,000 时约 **2,600 元**，前 4 周 **0 元**
- **生死线**：DAU 1 万。达不到就是几千块，达到了就是一份副业收入
- **最大风险**：子女不愿把卡片发到家庭群（邀请率 < 30%），增长杠杆会直接归零

**一句话判断：这是个"能做成小生意、做不成大生意"的产品，值得用 6 周试一次，但不值得投 6 个月。**

## 二、为什么选它（你给的三个前提下，几乎没有更好的选择）

你的前提：垂类实用工具 + 广告流量主变现 + 自己能写代码。

这三个前提组合起来，产品必须同时满足四个硬条件，缺一个广告模式就跑不通：

| 硬条件 | 为什么必须 | 小药盒 |
|---|---|---|
| 每天都打开 | 广告收入 = 曝光 × eCPM，低频工具永远赚不到钱 | ✅ 慢病用药每天 1–3 次 |
| 一家多人用 | 广告按人头计曝光，一个用户带 2–3 人是最便宜的获客 | ✅ 子女设、老人用、兄弟姐妹看 |
| 有自然搜索流量 | 没预算投流，只能吃微信搜一搜的长尾意图 | ✅ "吃药提醒""老人忘记吃药"意图极强 |
| 无资质门槛 | 医疗类目审核严，个人主体做不了问诊处方 | ✅ 纯提醒工具，不碰诊疗 |

**为什么不是别的**：记账/打卡类已饱和且无传播动机；证件照、房贷计算器是低频，撑不起广告；AI 工具类需要模型成本，广告收入盖不住 API 费用，且个人主体收款无门；电商类需要资质与供应链。

**这个产品真正的空隙是"家庭协同"**：市面上的提醒工具都是单人打卡，药企小程序的提醒是卖药附属品。而老人自己不会装小程序，子女会 —— 子女装完必然要拉人，这是唯一能免费放大的杠杆。

## 三、收入结构（这一节最需要你冷静看）

### 3.1 三档收入（已按真实广告频控重算，不是理论值）

| 指标 | 冷启动期 | 保守 | 中性（生死线） | 乐观 |
|---|---|---|---|---|
| DAU | < 100 | 3,000 | 10,000 | 30,000 |
| 月广告收入 | 0 元 | ≈ 2,600 元 | **≈ 9,000–11,500 元** | ≈ 45,000 元 |
| 月成本（自建） | ≈ 0（开发期本机 Docker）| ≈ 100 元 | ≈ 150–200 元 | ≈ 200–350 元 |
| 月净收入 | 0 | ≈ 2,500 | **≈ 8,800–11,300** | ≈ 44,300 |

> **v2 成本重算说明**：自建后固定成本主要为轻量应用服务器（2C2G 约 60–100 元/月，DAU 1 万升 2C4G 约 150–200 元/月）、域名约 5 元/月、HTTPS 免费证书、对象存储/CDN 另计。相比云开发的 ~31 元/月，**上线固定成本上升到 ~100 元/月量级，但相对 DAU 1 万的 9,000–11,500 元收入仍不是变量**。真正新增的风险不是钱，是 **ICP 备案的时间** 与自己管运维的时间。详细乘法模型见 `后端技术方案.md` §十一。

**成本纪律（一句话，省下来的钱比大多数优化都多）**：**任何图片上传前必须压缩到 ≤60KB**（`wx.compressImage` + 最长边 ≤1280）。一张 3MB 手机原图变成 0.05MB 是 60 倍的差；再叠加对象存储回源与 CDN 下行流量，**上线一段时间后账单会突然翻几倍，罪魁祸首基本都是未压缩的药盒照片**。这一条写进代码评审单点检查项。

**两个必须校正的认知**：
1. **我最初在 PRD 里写的"DAU 1 万 = 1.3 万/月"偏乐观 15–20%**。原因是插屏受"30 秒冷却 + 日上限 3 次 + 夜间免打扰 + 打卡后 10 分钟不弹"四重限制，人均只能跑到 0.5–0.8 次/日，而不是原先假设的 1.5 次。增长线把这个数改回来了，我采纳。
2. **流量主结算是代扣个税的**。个人开发者按劳务报酬预扣，账面 1 万实际到手约 8 千上下（年度汇算可退部分）。**做现金流规划时按账面 80% 折算。**

### 3.2 广告位排序（顺序本身就是风控策略）

| 序 | 位置 | 形式 | 月贡献(DAU 1万) | 留存风险 | 什么时候开 |
|---|---|---|---|---|---|
| 1 | 打卡成功页 | Banner | ≈ 1,600 元 | 极低 | W5（开流量主后第一个） |
| 2 | 周报解锁 | 激励视频 | ≈ 3,300 元 | 极低 | W6 |
| 3 | 首页看板 | 原生模板 | ≈ 2,300 元 | 中 | W7 |
| 4 | 第 4 个药品 | 激励视频 | ≈ 450 元 | 低 | W8 |
| 5 | 药品详情返回 | 插屏 | ≈ 1,500 元 | **最高** | W9（最后开） |

**为什么这个顺序**：先用最不可能伤留存的位建立基线，再一个一个加。每加一个观察 2 周，7 日留存跌幅 > 15% 就在 24 小时内关掉（后端下发开关，不用发版）。**同时开多个位，留存一跌你不知道是谁干的，就再也调不回来了。**

**坚决不做的广告**：打卡页（待服状态）任何广告、吸底 Banner、开屏插屏、红包/摇一摇类、强制看广告才能打卡、漏服预警页广告。这七类会同时杀掉留存和搜索排名。

### 3.3 这个产品只有一条收入腿（必须认清）

删掉付费出口后（个人主体收不了钱），收入 **100% 来自广告**；而设计上还主动关掉了老人端的插屏和激励视频 —— 老人端的 ARPU 几乎只剩 Banner，而 Banner 的 eCPM 只有 1–5 元。

这意味着两件事：

1. **所有收入压力压在"老人愿不愿意每天点一下"这一个行为上。** 不是压在功能多少、不是压在广告位设计，就是这一个动作。它一旦不成立，后面全是零。
2. **这不是一个"多开几个广告位就能补收入"的产品。** 加位就是拿留存换钱，而留存是唯一的本金。所以任何时候想加广告位，先问一句：我是在扩大收入，还是在提前支取本金。

**这笔账要这么算**（加任何广告位之前先算一遍）：

| | 金额 |
|---|---|
| 多挂一个广告位带来的收入 | ≈ **+1,500 元/月** |
| 若因此掉 10% 留存（DAU 1 万 → 9,000） | ≈ **−900 ~ −1,700 元/月**，且**不可逆** |

有付费会员那条收入腿的时候，这笔账可以算松（广告损失有别的补）。现在只有一条腿，算不得。**赚 1,500 花 1,700，还是永久的，这不是生意。**

**如果你想提高收入上限，唯一的路不是加广告，是把 DAU 做上去。** 而 DAU 依赖裂变，裂变依赖家庭协同 —— 所以这个产品的商业模型最终收缩成一句话：**一个家庭能拉进来几个人。**

## 四、六周落地路线

| 周 | 做什么 | 完成标志 |
|---|---|---|
| **W1** | 名称已审批通过「替你记着吃药」；**并行启动域名 + ICP 备案（2–3 周关键路径）** + 提交流程（类目选「工具-效率」，绝不选医疗）+ 设计定稿 + **.NET 10 解决方案骨架 + SQL 基线 V001–V003 + Domain 状态机 TDD** | 备案提交受理、`medbox` 库跑通、TDD 首轮红绿 |
| **W2–W3** | 核心闭环：JWT 登录 / 家庭组 / 药品与计划（每时间点独立剂量）/ 打卡 / 订阅消息推送（BackgroundService 时间轮）| 自己家的场景能完整跑一遍 |
| **W4** | 家庭协同：邀请加入、看板、漏服预警、周报 + **代客配置 50 个真实家庭** + **`checkin.correct`（管理员改状态）必须本周补齐** | 50 个家庭在真实使用 |
| **W5** | 累计 UV 过 1000 → 开通流量主 → 只上 A 位 Banner；**备案完成 → 上线部署** | 第一笔广告收入（可能只有几块钱） |
| **W6–W9** | 按顺序加广告位（D → B → E → C），每个观察 2 周 | 留存没崩，收入爬坡 |
| **W10–W12** | 放大或止损 | 见第七节止损线 |

**注意 W4 和 W5 是并行的**：攒 1000 UV 和写剩余功能要同时干。等做完再去找用户，等于把变现推迟一个月。
**注意 W1 的备案是新增关键路径**：它和写代码并行，若 W1 不启动，W5 上线会被硬卡 2–3 周——这是从云开发迁移到自建最容易漏掉的一步。

## 五、开工前必须先做的 5 件事（顺序不能错）

1. **小程序名称已审批通过**：「替你记着吃药」（唯一可用的对外名，所有文案、导航、分享卡统一用它）。
2. **★ 域名 + ICP 备案（W1 第一天，新增最高优先级）**：自建服务器必须域名 + 备案 + HTTPS，备案 2–3 周是硬约束，晚一天上线就晚一天。这是迁移自建后新冒出来的关键路径。
3. **提交 `sitemap.json` 允许搜索收录**首页、打卡页、周报页。这是搜一搜能不能进流量的技术前提，也是最容易被漏掉的一步。
4. **类目选「工具 → 效率」**。选医疗健康会被驳回（个人主体无《医疗机构执业许可证》）。
5. **申请三个独立的订阅消息模板**（提醒 / 漏服预警 / 周报）。**必须分开申请**，否则早药提醒会把额度吃光，导致漏服预警发不出去 —— 而漏服预警是这个产品最值钱的一环。
6. **想清楚广告行业屏蔽**：开通流量主当天勾选屏蔽医疗、药品、保健品、医疗器械。用药提醒里出现药品广告，是封号级违规。

## 六、必须守住的 6 条铁律

这六条是全案反复博弈后定下的，任何一条破了，产品会以某种不显眼的方式死掉：

1. **打卡主流程零广告**。老人点开就要能点按钮，任何东西挡在前面都会让他放弃一次，放弃一次就不再用了。
2. **老人端不显示"失败/错误"字样**。网络问题统一说"已记在本机，会自动重试"，不弹窗、不回退、不阻断。老人看到报错就以为坏了。
3. **老人的纠错权不给老人**。撤销按钮只在子女端。老人误触撤销的概率高于打错卡，纠错是管理动作。代价是子女必须能看见打卡时间戳，异常时间用琥珀色标注。
4. **完成率不含人工修改**。子女手动改的记录单独计数、不进分子分母。否则改两次就能刷到 100%，北极星指标当场作废。
5. **剂量按时间点独立设置**。降压缓释片、优甲乐、华法林都是早 1 片晚半片，统一剂量会让老人吃错药 —— 而且不会报错，只会安静地错。
6. **广告开关必须能远端下发**。任何一个广告位伤留存，要在 24 小时内关掉且不发版。
7. **每个设计参数必须配一个能证伪它的埋点。** 例：免责弹窗强制等待 1.2 秒，同时埋 `delay_ms` —— 如果大量点击堆在 1.2 秒边界，说明用户是在等按钮变亮而不是在读文字，那就得往上调。**一个参数配上能证伪它的数据，它才不是拍脑袋；没有埋点的参数，上线后没人能证明它对还是错。**

## 六之后：这些"矛盾"是有意为之，**不要统一化**

维护这套文档时，你会遇到下面这些"不一致"。它们不是没想清楚，是想清楚之后故意不一致的。**把它们"修正"成一致，比留着一处真 bug 更危险**，因为那会把有意的取舍改回无意的错误。

| 看起来像矛盾的地方 | 为什么必须保持不一致 |
|---|---|
| 老人端**不显示**漏服红条与周汇总，子女端全显示 | 老人看到红色告警的第一反应是焦虑而不是行动，他无法处理这个信息；发现漏服是子女的职责 |
| P44 解锁记录页空态**放**广告 B，其余空态不放 | 其余空态会挡住第一步主按钮；这页是纯浏览页，广告不打断任何操作 |
| P42 邀请落地页**不做双模**，整页用老人规格 | 这是全产品唯一不知道来者身份的一页 —— 知道身份就不需要他选了。身份未知时只能按最脆弱的一方渲染 |
| `late` 不设第五态，只用 `is_late` 布尔 | 状态徽标的唯一价值是一眼可辨，五态会稀释辨识度；迟到本质是"已服"的子集 |
| 剂量**永不省略**，但长药名可以让位换行 | 剂量是安全信息，省掉会吃错量；药名截断只是不便 |
| 家庭回执只渲染一行灰字，**不做**红点/弹窗/提醒 | "被看见"的价值是有人在意我；一旦做成提醒就变成压力，性质完全变了 |

**判断方法**：遇到两处不一致，先去找有没有一段文字解释过它。**有理由的不一致是设计，没理由的不一致才是 bug。**

### 每天只看一个数字
**每日打卡成功总次数。** 它比 DAU 更贴近收入（收入依赖打卡页和周报曝光），也是流失链路里最后一个还会动的数字，而且无法被运营动作污染（UV 能靠代客配置堆，DAU 能靠推送拉，打卡必须老人真的点）。

### 三个必须验证的假设（4 周内看数据）
| 假设 | 不成立的表现 | 不成立怎么办 |
|---|---|---|
| 家属协同真的会发生 | 邀请率 < 30% | 先归因：有动作没完成 → 改落地页；根本没动作 → 打电话问 10 个人"为什么没发"，答案决定是改产品还是改定位 |
| 老人能收到提醒 | 订阅授权率 < 40% | 改走"子女代持"模式：只给子女推送，子女打电话提醒。收入可能不降反升（子女端 eCPM 更高） |
| 广告不伤留存 | 7 日留存跌超 15% | 按序拆弹：先关插屏 → 再关看板 Banner → 再关全部 Banner。每次只拆一个，观察 7 天 |

### 止损线（写死，不临场动摇）
> **W12 末同时满足三条 → 停止 C 端投入：① DAU < 800 ② 30 日留存 < 10% ③ 实测 K < 0.3**

**为什么 W12 就止损**：这个产品的成本不是钱（自建上线约 100 元/月，DAU 1 万约 150–200 元/月），是你一个人的时间 —— 自建还要额外背运维。再多投 3 个月 ≈ 300 小时，同样 300 小时接一单外包的确定收益是 8,000–30,000 元，而 DAU 从 800 爬到 1 万的概率（无投放、K<1 的垂类工具）低于 5%。这是期望值计算，不是悲观。

### 如果失败，Plan B
1. **B 端贴牌**：改造成白标版卖给社区养老中心、连锁药店、健康管理公司，3,000–8,000 元/家实施 + 2,000–5,000 元/年维护。**前提：必须能签合同开发票，得先办个体工商户（约 500–1,500 元，5–10 个工作日）。**
2. **定制开发外包（现金流最快）**：把这套东西当作品集接"适老化/健康管理"类小程序单，8,000–30,000 元/单。**六周做出来的东西，同时也是你最硬的简历。**

## 九、主理人最后三句话

1. **这个产品唯一真正难的事不是写代码，是让 50 个真实家庭用起来。** 增长线给的方案里最有效的一招是"代客配置"——你替用户把药盒搭好，他只负责点。这活很土，但它决定了前 4 周能不能攒够 1000 UV。
2. **广告变现的残酷之处在于：你所有的产品决策都在为"留存"服务，而留存最终要换成曝光。** 所以每一次"要不要加个广告位"的犹豫，答案都是先不加 —— 加错了要 2 周才能发现，减回来要再 2 周，而 DAU 到 1 万才有意义。
3. **不要爱上这个产品。** 它有明确的止损线，到了就走，Plan B 里那条"接外包"的收益比它确定得多。做它最大的价值，是你会拥有一套完整的、能拿去接单的作品和文档。
