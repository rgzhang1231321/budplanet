## 〇、结论摘要

核心闭环是通的，而且异常分支处理得比多数同类产品细（假成功、离线队列、`?dose=` 失效、加载态与真空态分离都做过了）。问题集中在三处：

| 类型 | 问题 | 后果 |
|---|---|---|
| **A. 漏斗断在"设置完成之后"** | 没有邀请引导、没有提醒额度续期、没有代打卡 | 家庭协同是本产品唯一的增长杠杆（PRD §二），但设置完成后没有任何动作推用户去拉人 |
| **B. 半成品** | 有展示位无录入位（药品备注）、有表结构无入口（暂停用药 / 提前提醒 / 多家庭） | 用户遇到真实场景时无路可走，只能删数据或手动绕过 |
| **C. 老人端误导** | 提前打开打卡页会被渲染成"该吃药了"；无"今天吃了几次"的汇总 | 可能提前服药（安全），且老人无法自证"我吃了" |

计数：**P0 5 条 / P1 7 条 / P2 9 条**，其中 8 条已出原型（见 `prototypes/2026-11-02-体验补全原型.html`）。

## 二、P0：流程断点（5 条）

### P0-1　子女无法替老人补记"已服"（pending → taken 无入口）

- **证据**：`pages/home/index.ts:163-167`。`pending` 行的 ActionSheet 只有 `['改为跳过']`；`taken` 行才给"改为漏服/跳过"。
- **真实场景**：老人打电话说"我吃了，那个按钮我不会点"。子女唯一能做的操作是"改为跳过"——把一次**已服**记成**跳过**，周报完成率被拉低，且语义完全错。
- **契约是允许的**：`契约冻结表.md` §7 明确 `pending → taken` 合法，通道走 `checkin.submit{status:'taken'}`。
- **不是权限问题**：admin 本来就有 `checkin.correct` 权限，只是前端没给这条通道。
- **改法**：`pending` 行菜单加「替他记上（已服）」，二次确认里显式写"这是**代 XX 记的**"，并在行尾保留"已修改"痕迹（`is_corrected` 或审计日志），避免子女刷完成率。
- **原型**：屏 3「代打卡确认」。

### P0-2　提醒额度耗尽后静默失效

- **证据**：`pages/settings/index.ts:56` 有 `还能提醒 N 次 / 提醒额度用完了，点一下补上`；但**首页、打卡成功页、药品保存后的引导之外，没有任何地方提示额度**。`home/index.wxml` 无额度元素。
- **机制**：微信一次性订阅 = 授权一次发一条。`quota` 归零后后端直接跳过推送（`notify` 域），前端不会收到任何错误。
- **后果**：用户以为"我设了提醒"，实际第二天起就**收不到**。这是"产品失效但用户无感知"，比任何视觉问题都严重——它会以"老人漏服"的形式暴露，而团队会误判成留存问题。
- **改法**：① 首页顶部加"提醒已用完"细条（只在 `quota.CHECKIN===0` 时出现，可关闭 24h）；② 打卡成功页在额度 ≤1 时预埋一句"下次提醒需要你点一下"；③ 统一一个"提醒额度"页，把 CHECKIN / MISSED / WEEKLY 三个模板的额度、授权状态、补授权按钮放一起。
- **原型**：屏 2「提醒额度」+ 屏 1 顶部告警条。

### P0-3　首次设置没有"邀请家人"这一步（漏斗断裂）

- **证据**：`home/index.wxml:61-68` 空态只有两个分支——没服药人 → 「添加服药人」；有服药人没药 → 「添加第一个药品」。加完药、订阅引导关掉之后，**主路径上再没有任何指向邀请的动作**。邀请入口在「我的 → 家庭组与成员」（`profile/index.wxml:35`），三步深。
- **PRD 的漏斗目标**：设置完成 → 邀请至少 1 人 ≥ 50%（PRD §七）。这个动作现在**不在路径上**，只能靠用户自己想起来。
- **改法**：首页空态改为"设置清单"三行——① 添加服药人 ✓ ② 添加第一个药 ✓ ③ **把邀请码发给家人**（未完成时高亮，完成后整卡消失）。清单本身也是留存提示：三天没加药会重新出现。
- **原型**：屏 1「首页 · 设置清单」。

### P0-4　老人提前打开打卡页，会被渲染成"该吃药了"

- **证据**：`pages/checkin/index.ts:128-134`。`build()` 取**最早一条 pending**，不比较 `due_ts` 与当前时间；`headText` 只有 `${partOfDay} ${due_time}`（`:172`），主按钮恒为「我已服用」。
- **后果**：早上 6:20 打开（8:00 的药），页面标题写"早上 08:00"，按钮写"我已服用"，**没有任何"还有 1 小时 40 分"的提示**。老人可能据此提前服药。对缓释片、降糖药这是真实风险。
- **同类问题**：老人端首页「去打卡」不带 `dose` 参数（`home/index.ts:213-215`），必然落到最早 pending，同样无时间语义。
- **改法**：`pending` 视图分三态——`now < due_ts - 30min` → 显示"还没到点 · 还有 X 小时"，主按钮降级为"我提前吃了"（次要按钮）；`due_ts-30min ~ due_ts+missedThreshold` → 正常打卡；超时 → 现有逻辑。老人端首屏同样加一行"下一次 12:30"。
- **原型**：屏 4「打卡页 · 未到点」。

### P0-5　漏服告警条没有"已处理"出口

- **证据**：`home/index.wxml:36-39` 红条只有「去提醒」一个动作；`home/index.ts:88-103` 只要存在 `status==='missed'` 的行就常驻。
- **后果**：子女打完电话、确认老人已经补服，红条**仍然在**（状态没变）。每次打开首页都被同一条告警再扎一次，一周后用户对红条脱敏——真正的新漏服反而看不见。
- **改法**：红条加次要动作「已联系」（本地记 `ackAt`，当天不再展开为红条，降级为一行灰字"08:00 那条已联系过"）。**不改服务端状态**，因为"联系过"不等于"吃了"。
- **原型**：屏 1 红条右侧。

## 三、P1：应有未有（7 条）

### P1-1　药品无法暂停，只能删除

- **证据**：`db/migrations/V001` 的 `plans.status` 已定义 `active | paused | finished`，但全仓**没有任何 pause / resume 的 action、接口或 UI**（`契约冻结表.md` §5 `plan` 只有 `create/update/finish`）。
- **真实场景**：医生让停两周、术前停药、感冒加药后停。当前只能"删除这个药"——历史记录跟着断（`medicine.archive` 软删），或者每天手动点"今天不吃"（污染完成率）。
- **改法**：药品详情加「暂停用药」→ 选结束日期（默认 7 天后）→ `plans.status='paused'`；到期自动恢复。列表与首页对该药显示"已暂停 · 8月20日恢复"，不计入完成率分母。
- **成本**：需新增 `plan.pause` / `plan.resume`，属契约增项，**必须先报主理人升版本**。
- **原型**：屏 5「药品详情 · 暂停」。

### P1-2　药品备注有展示位、无录入位（饭前/饭后填不进去）

- **证据**：`medicine-detail/index.wxml:24-27` 有"备注"行读 `med.note`；但 `medicine-form` 的表单**没有 note 字段**（三个 step 只有药名/规格/剂量/时间/周期），`types/api.ts:118` 的 `note` 从未被写入；`medicine.list` 契约出参也不含 `note`。结果：**这一行永远显示"—"**。
- **为什么重要**："饭前吃 / 饭后吃 / 随餐"是用药安全信息，比规格重要。老人到点看到"二甲双胍 1 片"，不知道饭前饭后。
- **改法**：Step 2 加一行"什么时候吃"快捷 chips（饭前 / 随餐 / 饭后 / 睡前 / 不限）+ 自定义备注；打卡卡片顶部显示该标签。需 `medicine.list` 补 `note`（契约已漏登，批 4 一并补）。
- **原型**：屏 4 打卡卡片上的「饭后」标签 + 屏 5 详情页。

### P1-3　多家庭无切换入口

- **证据**：`store/index.ts:26` 存了 `family.all`，`launch/index.ts:56` 用它判断早退，但**没有任何页面渲染它**。`loadFamily()` 固定取 `family.all[0]`（`store/user.ts:64`）。
- **后果**：管自己父母 + 配偶父母两个家的用户，永远只能看到第一个家，第二个家的药单**无法进入**。这是"家庭协同"产品里很常见的人群。
- **改法**：首页标题右侧加家庭名下拉（子女端）；「我的」页家庭行显示"当前：张家 / 共 2 个家"。切换后 `set('family.fid')` + `loadFamily()` + `refreshToday()`。
- **原型**：屏 1 标题栏。

### P1-4　邀请发出后没有"待加入"反馈

- **证据**：`packageManage/pages/family/index.wxml:44-59` 只渲染 `members`（已加入）。管理员复制码、转发卡片之后，**无法知道对方进没进**，也没有"再提醒一次"。
- **后果**：这是漏斗里最贵的一步（邀请 → 加入），却是唯一一个**完全无反馈**的步骤。
- **改法**：成员列表下方加"已发出邀请 · 等待加入"占位（本地记录 `invitedAt` + 昵称），48 小时后变成"还没加入？再发一次"。
- **原型**：屏 6「家庭组 · 待加入」。

### P1-5　"详细报告"没有洞察，付费（激励视频）价值不足

- **证据**：`packageReport/pages/report-detail/index.wxml` 只有三块——完成率、7 天日历、漏服明细列表。而 `weekly/index.wxml:47-48` 卖的是"含每次漏服的具体时间与**趋势**"。
- **后果**：用户看 15 秒视频，换来的是免费周报页已有的信息 + 一张日历。这是 PRD 里收入最高的一位（≈3,300 元/月 @DAU 1 万），**交付价值撑不住**。
- **改法**：加两块洞察——① 按药维度（哪种药漏得最多）；② 按时段维度（早/中/晚漏服热力条）；③ 与上周对比的一句话结论（"晚上这次比上周多漏了 2 次"）。数据都在 `schedule.week` 的 `missList` 里，**不需要新接口**。
- **配套改法（`增长与变现方案.md:360` 的第 2 条手法）**：免费周报页要**先给半截信息**——"漏服 3 次（周三早、周五晚、周日晚）"照旧显示，锁住的应该是"具体几点、连续漏了几天、按药分布"。现在是免费版已经给完，解锁版没有增量。
- **原型**：屏 7「周报详情 · 洞察」。

### P1-6　"导出给医生看"实际导出的是全量数据包

- **证据**：`report-detail/index.ts:92-107` 的 `onExport` 调的是 `call('user','export',{})` —— 与「我的 → 导出我的数据」是**同一个接口**，返回全量数据下载链接。`unlocks/index.wxml:60` 又把它列为"看视频可解锁"的第三项，但 `utils/ad.ts:20-23` 的 `PRODUCT` 只有 `MED_SLOT` / `WEEK_REPORT`，**没有导出商品**。
- **后果**：三处文案（周报按钮 / 解锁页清单 / PRD §6.4）承诺"近 30 天复诊报告"，实现是"全量数据导出"。用户拿到一个 JSON 包，给不了医生。
- **不是没人想到**：`增长与变现方案.md:345` 已把它列为"当前方案里唯一没被开发的高价值场景"，`:628` 标为 `report.export` / P1 / W8 前必须上，且写明"已下单 backend-cloud-dev"。**问题是前端先接错了接口**——`report.export` 不存在时不该回落到 `user.export`，两个语义完全不同。
- **合规边界（照 `:354-357` 执行，别自己加）**：不含建议 / 不含诊断 / 不出现"医嘱"；完成率必须标注为"**用户记录的统计**"，**不能写成"依从性评估"**。
- **改法**：要么做一个真正的"近 30 天用药报告"（单页 A4、可存图/PDF），要么把三处文案改成"导出我的数据"。**建议前者**——它是 PRD 里把激励视频观看率从 0.22 提到 0.33 的核心场景。
- **原型**：屏 8「复诊报告预览」。

### P1-7　老人端没有"今天吃了几次"的汇总，也没有历史入口

- **证据**：`home/index.wxml:78-116` 老人端首屏 = 日期 + 「去打卡」+ 药单 + `recentText`。没有 `X/Y 已服` 的汇总（子女端有 `ov`）；`custom-tab-bar` 在 elder 模式整体隐藏，`settings` 老人端 6 行里也没有周报/历史。
- **后果**：老人最常问的一句话是"我早上吃了没"。他必须逐行读药单才能回答，而药单只有 4 行以内还好，多了就要翻。
- **改法**：老人端首屏加一行大字"今天 3 次，已吃 2 次"；设置页加「我的记录」入口（只读、近 7 天，不做完成率评价，避免制造焦虑）。
- **原型**：屏 4 顶部。
