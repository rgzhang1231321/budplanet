# 替你记着吃药 · 产品介绍

> 微信小程序「替你记着吃药」（仓库代号 BudPlanet，后端工程名 MedBox）
> 对外唯一名称：**替你记着吃药**（已通过微信名称审批，文档内「小药盒」为历史代号）

---

## 一、一句话

**子女在微信里给父母设好吃药提醒，老人到点收到微信通知、点一下「我已服用」，全家都能看到今天吃没吃。**

只做三件事：**提醒 + 记录 + 家属可见**。
不问诊、不卖药、不建药品库、不给任何用药建议。

---

## 二、它解决的是一件很具体的事

**痛点**：父母 60 岁以上，高血压/糖尿病/心脏病等慢病，每天要吃 1–3 次药。
子女不在身边，每天打电话问"药吃了没"——问多了烦，父母还会骗你说吃了。
老人自己会忘、不会记、也不想管。

**现状为什么不够用**：

| 常见方案 | 差在哪 |
|---|---|
| 手机自带闹钟 | 只响不记录，不通知家属，不吃药也没人知道 |
| 健康管理 App | 太重，老人装不上、不会用，还要注册登录 |
| 药企/连锁药店小程序 | 核心是卖药，提醒只是附属功能，绑定自家药品库 |
| 微信里的同类小工具 | 都是"单人打卡"，**没人做家庭协同这一层** |

**我们的空隙 = 家庭协同**。老人自己不会装小程序，但子女会；子女装完必然要拉人（爸妈、兄弟姐妹）。
一次获客带来 2–3 个用户，这是这个产品唯一免费的增长杠杆，也是所有设计取舍的锚点。

---

## 三、两种人，两个界面（双端双模）

同一个小程序，同一路由，按 `mode` 渲染两套界面。

### 子女端 —— 信息密度

- **今日看板**：全家每个人的今天吃没吃，完成率进度条
- **药品管理**：按服药人分组的药品清单，剂量/时间点一眼看清
- **周报**：本周完成率、漏服次数、逐日打卡标记、历史趋势
- **我的**：家庭组、成员管理、界面模式切换、订阅额度
- 打卡后可 **3 秒撤销**（纠错是管理动作，只给子女）

### 老人端 —— 极致大字

- 首页只有一句「今天要吃的药」和几个大按钮
- 打卡页：超大字号药名 + 剂量 + **一个**「我已服用」大按钮
- 辅助操作只有两个：「稍后提醒（15 分钟）」「今天不吃」
- 界面上不出现「失败 / 错误」字样，网络问题统一说"已记在本机，会自动重试"
- 老人端单独一个广告位，可单独关停

> **判定只用 `mode`**（`elder` / `admin`），`role` 只管权限，二者解耦。界面上的人教版/大字版可随时在「我的 → 界面模式」切换，选错了也不影响任何数据。

## 四、核心功能

### 1. 家庭组
一个用户可创建/加入多个家庭组，组内分「管理员 / 成员」两种角色。
邀请方式为**分享卡片 + 邀请码**双通道 —— 老人不会输邀请码，所以邀请码可以直接用微信/短信发过去，粘贴即入组。

### 2. 服药人档案
姓名、称呼（爸/妈/爷爷）、头像；一个家庭组支持多个服药人（父母双方都能管）。

### 3. 药品与计划
- 药名支持手写输入 + 常用药快捷选择
- 每日 N 次，早/中/晚快捷模板 + 自定义时间点
- **剂量按时间点独立设置**（早 1 片 / 晚半片这类吃法，单剂量模型表达不出来，错了还不报错）
- 支持"连续 30 天"周期用药与长期用药

### 4. 提醒与打卡
- **微信订阅消息**到点推送（一次性订阅：授权 1 次 = 1 条额度）
- 打卡页超大卡片 + 单个主按钮，**5 秒内完成**
- 弱网/断网不阻断：打卡进本地队列，恢复网络自动补传并去重

### 5. 漏服预警（这一环最值钱）
超过设定时间 60 分钟仍未打卡 → 自动推送家庭管理员：
「爸爸今天 8:00 的降压药还没吃」。
这一条推送就是用户留下来的理由，也是分享到家庭群的话术。

### 6. 家庭看板与周报
今日状态四态：待服 / 已服 / 漏服 / 跳过。
周报推送完成率与漏服明细，可转发家庭群。
**手动改判的记录单独计数、不进完成率分子分母** —— 否则改两次就能刷到 100%，指标当场作废。

### 7. 广告位（变现核心）
打卡成功页 Banner / 看板 Banner / 周报激励视频 / 药品详情返回插屏 / 第 4 个药品起激励视频。
所有广告位**可远端下发开关**，任何一个位伤留存，24 小时内关掉且不用发版。

## 五、刻意的"不做"

第一版砍掉的东西，和做出来的东西一样重要：

- ❌ 药品数据库、条码扫描识别（合规风险 + 成本高）
- ❌ 在线问诊、用药建议、相互作用检查（**医疗合规红线，个人主体绝对不能碰**）
- ❌ 药品购买 / 电商跳转（涉及资质与售后）
- ❌ 血压血糖数据记录（先验证核心留存）
- ❌ App / H5 多端同步（只做小程序）
- ❌ 打卡主流程上的任何广告（老人点开就要能点按钮）

还有几条"有理由的不一致"，是设计不是 bug：

| 看起来矛盾的地方 | 为什么必须保持 |
|---|---|
| 老人端**不显示**漏服红条与周汇总 | 老人看到红色告警第一反应是焦虑不是行动，他处理不了这个信息 |
| 邀请落地页**不做**双模，整页用老人规格 | 这是全产品唯一不知道来者身份的一页，身份未知只能按最脆弱的一方渲染 |
| `late` 不设第五态，只用 `is_late` 布尔 | 状态徽标的唯一价值是一眼可辨，五态会稀释辨识度 |
| 剂量**永不省略**，长药名可以让位换行 | 剂量是安全信息，省掉会吃错量；药名截断只是不便 |

## 六、技术实现

| 层 | 选型 |
|---|---|
| 小程序 | 微信原生（TypeScript，仅 tsc 做类型门禁，编译交给开发者工具） |
| UI | 老人端与主包自研；子女端分包用 TDesign 1.17.0 |
| 后端 | .NET 10 Web API，四层：Domain / Application / Infrastructure / Api |
| 数据库 | PostgreSQL 18（库 `medbox`，schema 由 `db/migrations/V*.sql` 顺序构建） |
| 通知 | 微信订阅消息，6 个 BackgroundService 驱动（物化 / 提醒 / 推送 / 周报 / 归档 / 统计） |

工程约束（几条关键的）：

- **接口契约冻结**：11 个业务域的字段、action 名、错误码、四态枚举、`server_ts` 逐字不可改，前后端只认 `docs/契约冻结表.md`
- **禁用 EF Core Migrations**：建表改字段一律走 append-only 的 `V{NNN}__xxx.sql` 顺序脚本，执行器记 SHA-256，改历史脚本直接报错中止
- **确定性主键**：`dose_id = ${plan_id}_${date}_${slot}`，状态迁移靠 `UPDATE ... WHERE status=...` 的影响行数当 CAS
- **不吞异常**：领域异常统一映射为 `{code, data, msg}`，其余记结构化日志后返回 1009
- **密钥不进仓库**：`JWT__SECRET` / `AppSecret` / 数据库口令全部走环境变量或 User Secrets

当前规模：**17 个页面 + 14 个基础组件 + 111 个后端单测全绿**，里程碑 M1–M5 已完成，处于真机验收阶段。

## 七、合规与隐私

这个产品跑在"工具 → 效率"类目下，**绝不选医疗服务类目**（个人主体无《医疗机构执业许可证`）。

- 首次使用必须确认免责：「本工具仅提供服药提醒服务，不提供任何医疗建议，用药请遵医嘱」
- 文案禁区：不出现"治疗""疗效""推荐用药""替代医生""根据症状判断"
- 药品名与用药记录属敏感健康信息：明示《隐私政策》，仅存于云端并与 openid 绑定，不对外共享、不做用户画像出售
- 广告合规：流量主开通当天必须勾选屏蔽医疗、药品、保健品、医疗器械
- 订阅消息合规：一次性订阅必须由用户主动点击授权，不诱导、不批量静默请求

完整文本见 `docs/合规与通知文案.md`，页面文案一律照抄，不自行编写。

## 八、商业模式

个人主体小程序无法申请微信支付商户号，所以**收入 100% 来自广告流量主**，没有第二条腿。

| 形式 | 实际 eCPM | 用在哪 |
|---|---|---|
| Banner | 1–5 元 | 打卡成功页、看板（基本盘） |
| 插屏 | 5–15 元 | 药品详情返回（最后开，频控最严） |
| 激励视频 | 30–80 元 | 周报详细报告解锁、多加 1 个药品名额 |

**广告位按序开，不同时开**：先用最不可能伤留存的位建基线，每加一个观察 2 周，7 日留存跌幅 > 15% 就在 24 小时内关掉。
同时开多个位，留存一跌就不知道是谁干的，再也调不回来。

成本纪律一句话：**任何图片上传前必须压缩到 ≤60KB**。一张 3MB 手机原图变 0.05MB 是 60 倍的差，叠加对象存储与 CDN 后账单会突然翻几倍。
